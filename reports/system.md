# システム開発ターミナル 報告（2026-08-01・第3便）

使用モデル＝Opus 5（1M context）／作業＝通知メールに残っていた「発送の記述」の切り分けと是正

## 1. 結論

代表が受信されたメールに残っていた発送の記述**6項目はすべてShopifyのサンプルデータによる描画**だった。
本番の実データでは出ない。**それで終わらせず、発送に関する3ブロックを削除**したので、
**本番でもテスト送信でも二度と出ない**。

## 2. サンプルデータだと断定できる根拠（4つ・いずれも実測）

1. **通貨**＝当店はJPY（`¥{{amount_no_decimals}}`）。メールは **$79.11 CAD（カナダドル）**。実データなら `¥3,300`。
2. **商品名**＝メールは **Example Product #1 / #2**。当店のサブスク商品は「あつぺくとシステム利用料（月額）」1点のみ。
3. **住所**＝請求先が **150 Elgin St, Ottawa, カナダ**（Shopify社の所在地）。「東京都 横浜市 出荷通り」も実在しない組合せ。
   ★**「運送会社」はテンプレートのラベルではなく、サンプル住所の会社名欄**（テンプレート全文検索で「運送」0件）。
4. **商品設定の実測**＝サブスク商品の `requires_shipping = false`（Admin API・ストアフロント両方で一致）。
   実プランは **「1か月ごとに配達」＝月額**（「4週間の前払い…」はサンプルのプラン名）。

**★未確認**＝実際のサブスク請求での描画（契約0件・`subscriptionContracts` はAPIスコープ未承認で読めない）。

## 3. 直したこと

**サブスク3本（new / payment_reminder / payment_failure）共通**
- 「受取／配送」の小計行ブロックを**削除**（`shipping_price > 0` で囲んでいたがサンプルには金額が入り通り抜けていた）
- 「配送先住所」ブロックを**削除**（＝運送会社・出荷通りもこれで消える）／「配送方法」ブロックを**削除**
- 販売プラン名の差し込みを固定文言 **「毎月更新」** に置換（3箇所×3本＝9箇所。プラン名はアプリ所有で変更不可）
- 削除箇所にはLiquidコメントで理由と復旧方法（「デフォルトに戻す」で全文復旧可）を残した

**subscription_new のみ**＝本文「◯週間ごとに承ります」→ **「毎月」に固定**（サンプルでは4週間ごとと出ていた）

**order_confirmation（同じ観点で見直した結果）**
- **件名を発送の有無で分岐**（発送あり＝ご注文の確認／発送なし＝お手続きの確認）
- 分岐の外に残っていた「注文」「発送」の文を `requires_shipping` で分岐
- **二重敬称「様 様」「様様」3箇所を修正**（Shopify初期文面のままの誤り）
- 発送関連ブロックは `requires_shipping and shipping_address` 等で正しく囲まれていることを確認
