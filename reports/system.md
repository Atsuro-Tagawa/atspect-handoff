## 2. 作った経路と使い方

```bash
cd C:\Users\ataga\atspect-system

node scripts/artist-i18n-update.mjs show   --name "二川 幸夫"        # 現状を2箇所並べて見る（読み取りのみ）
node scripts/artist-i18n-update.mjs verify                          # 全625名の不一致を点検＋CSV出力（読み取りのみ）
node scripts/artist-i18n-update.mjs plan   --file <指示書.json>      # 差分確認＋バックアップ（書き込みなし）
node scripts/artist-i18n-update.mjs apply  --plan <plan_*.json> --yes   # 実反映（要 SHOPIFY_ALLOW_WRITE=1）
node scripts/artist-i18n-update.mjs restore --backup <backup.json> --yes  # 戻す
```

指示書はJSONで、作家名・理由（必須）・直したい言語だけを書きます。**書いた言語・キーだけが変わり、他は元のまま**です。
テンプレート＝`atspect-system/scripts/artist-i18n-templates/例_指示書.json`。

満たしている条件（指示された必須条件）：

- **個別フィールドと `artist_i18n` を同時に更新**＝1作家につき**1回の `metaobjectUpdate`** で両方を送るため、片側だけ更新される状態が原理的に起きません
- **8言語すべて（deを含む）**に対応
- **更新前にバックアップ**＝`plan` の時点で対象作家の全40フィールドを `C:\Vault\ARTS-RESPECT\_backups\_auto\artist-i18n\<日時>_<ラベル>\` へ保存。`apply` はバックアップの**中身を検証**してからでないと動きません
- **dry-run で差分確認してから apply**＝`plan` が「現在→更新後」を1項目ずつ表示
- **1名ずつ／指定した数名だけ**を対象にできます

## 4. ★この経路で更新**できない**もの

| できないこと | 理由 |
|---|---|
| `handle`（URLスラグ） | リダイレクト設計が必要 |
| `name_ja`（作家名） | 照合キーのため |
| 画像（`portrait` `hero_image` `masterpiece_*`） | 対象外。`restore` でも書き戻しません |
| 作家の新規作成・削除 | 既存レコードの更新のみ |
| `masterworks` の自動ミラー | 実データが配列形式599件／言語オブジェクト形式25件に割れ、「、」連結での導出一致率も93.1%＝41件を取り違える。`i18n.masterworks` と `flat.masterworks_text` の**両方明示**が必要 |
| 個別フィールドだけを直すこと | **意図的に禁止**（片側だけ直すと食い違うため）。`i18n` に書けば両方に入ります |
| CSV正本への反映 | このツールはShopifyのみ。CSV側は別途手作業 |
| 複数作家をまとめた取り消し | Shopify APIにトランザクションが無いため。1名ずつ実行を推奨（失敗時の状態と対処は手順書§6の表に明記） |

## 5. Codexによる独立レビュー（指示どおり2観点のみ・1依頼1観点）

| 観点 | 結果 |
|---|---|
| ①2箇所を確実に同時更新するか | **実在の欠陥を検出→修正済み。** `flat` でミラー対象の個別フィールドを単独指定でき、2箇所を食い違わせる入力が作れた。ミラー対象は `flat` 禁止にし、指示書検証と `buildUpdate` の二重で弾くようにした |
| ②失敗時にデータが壊れないか | **5点を修正。** (1)更新エラー時に「書き込みは行われていません」と根拠なく断定していた→実測して報告 (2)`restore` に楽観ロックが無く第三者の変更を巻き戻す→`applied.json` で検出（`--force` で明示的に上書き） (3)バックアップは存在確認のみ→中身を検証 (4)書き戻せない参照フィールドを他の不一致と区別 (5)検証失敗時に「書き込みは実行済み＝中途半端」と明示し復旧コマンドを提示 |

Codexが挙げたうち「複数作家の途中失敗」「ネットワーク断」はShopify API仕様上コードで解消できないため、修正ではなく**手順書に正直に文書化**しました。
