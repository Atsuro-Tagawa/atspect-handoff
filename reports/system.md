## 結論

### 1. 司令塔の見立て「8言語連結が原因」は **主因ではありません**

インデックスを阻害する技術的要因は **一つも見つかりませんでした**。

| 確認項目 | 結果 |
|---|---|
| robots.txt | `Allow: /`・sitemap宣言あり ✅ ブロック無し |
| sitemap.xml | 正常（商品3点＋固定ページ11件ほか） ✅ |
| HTTPヘッダ | 200 OK・`X-Robots-Tag` **無し** ✅ |
| トップの meta robots | **無し**（＝既定のindex,follow） ✅ |
| canonical | 自己参照・正常 ✅ |
| title / meta description | **日本語のみ。8言語連結ではない** ✅ |
| パスワード保護 | 解除済み ✅ |

8言語混在は「インデックスされない原因」ではなく「関連性・品質評価を薄める問題」です。

**ただし「まだクロールされていないだけ」と断定もできません**（Codexの指摘で訂正）。Search ConsoleのURL検査が無い限り、未発見／発見済み未クロール／クロール済み未登録／canonical統合／実は登録済み、を区別できません。

### 2. 司令塔の報告のうち1件は実測で否定されました

**og:locale:alternate は「de_DE 1件」ではなく、8言語すべて揃っていました**（ja_JP＋en/zh_CN/zh_TW/ko/fr/es/deの7件）。同名property のmetaを1件に畳んで表示するツールで見るとde_DEだけが見えるためと思われます。**修正不要でした。**

hreflangタグが無いこと、artist-guideのnoindex、og:priceのカンマは、いずれも報告どおりでした。

### 3. ★調査の副産物として、ライブの表示バグを発見しました（本件で最も価値のある発見）

エピグラフの **英・独・仏・西・韓の5言語が、画面上で単語が繋がって表示されています**：

```
Lifecomestoanend;
artmustnevercometoanend.
```

ブラウザで実際に英語表示へ切り替え、**スクリーンショットで目視確認済み**。ja/zh-cn/zh-twは分かち書きしないため正常です。ページ全体を走査した結果、**エピグラフ1箇所に限定**されています。

**原因**：`sections/atspect-ticker.liquid` の単語分割5言語の分岐は、空白を出す意図のコード `{% unless forloop.last %} {% endunless %}` を既に持っていますが、**直後の `{%- assign` の空白除去指定がその空白を飲み込んでいる**と推定されます（ライブとローカルが完全一致であることを確認済み）。

**修正案（5行・各1箇所）**：

```liquid
変更前: ...{{ word }}</span>{% unless forloop.last %} {% endunless %}{%- assign en_i = ...
変更後: ...{{ word }}</span>{%- unless forloop.last -%}&#32;{%- endunless -%}{%- assign en_i = ...
```

`&#32;` ならLiquidの空白制御で消えず、見た目が直り、コピーも読み上げも効きます。**日本語・中国語の分岐は触らないため字間は一切変わりません。**

対象行＝54(en) / 99(ko) / 108(fr) / 117(es) / 126(de)。**事前承認された軽微修正2件に含まれないため実装していません。指示があれば即座に反映できます。**

### 4. og:price:amount のカンマ ✅ 本日修正・本番反映済み

実測結果：`300000` / `180000` / `160000` — カンマ消失を確認。

補足：**商品JSON-LDの `price` は元から `300000.0` でカンマ無し＝正常でした。**Googleのリッチリザルトが読むのはJSON-LD側なので、**このカンマはSNSシェア表示に限定した問題でSEOへの影響はありませんでした**（当初の見立てより軽微）。

## 代表がやる操作：Google Search Console 登録

外部から観測できる認証手段（metaタグ・DNS TXT・GA/GTM）は一つも見つかりませんでした。

1. https://search.google.com/search-console にログイン
2. 「プロパティを追加」→ **「ドメイン」**を選ぶ（www有無・http/httpsをまとめて扱えるため）
3. `atspect.com` と入力
4. 表示される **DNS TXTレコード**をコピー
5. **Xserver** のDNSレコード設定で **TXTレコードを1件追加**（※既存のSPFは消さず追加のみ）
6. GSCで「確認」を押す（DNS反映に最大48時間）
7. 「サイトマップ」→ `sitemap.xml` を送信
8. **「URL検査」**でトップと商品3点を検査し、**Google選択canonical**と**インデックス未登録の理由**を記録

**この8の結果が、次に何をすべきかを決める唯一の材料です。**

### hreflangを推奨しない理由（Codexも同意）

hreflangは言語別の**別URL同士**を対応付ける仕組みです。同一URLに8言語分を書いても、Googleが取得できる文書は1件しかなく、検索結果で選び分ける対象が存在しません。x-defaultの単独追加も実益なしです。言語別URL化はShopify Markets不使用の確定事項と両立しません（Liquidは任意のクエリパラメータを読めないため）。

### 案6を保留推奨とする理由

「効くかどうか分からない仮説」に対して最もコストとリスクが高い改修を先に払う形になります。**GSCで具体的な未登録理由が出てから判断すべき**です。営業が検索流入を前提にしていない以上、急いで賭ける必要はありません。

### `display:none` はクローキングか → リスクは低い

Googleの隠しテキスト違反は「順位操作目的で隠したテキスト」が対象で、操作に応じて表示されるものは違反ではないと明記されています。Googlebotにも利用者にも同じHTML/CSS/JSを返しており、手動対策の現実的リスクは低いです。

## Codexの指摘で訂正した点

| 論点 | 当初 | 訂正後 |
|---|---|---|
| 主因の断定 | 「未クロールが主因」と断定 | GSC無しでは確定不可 |
| GSCの因果 | 「未登録だから発見されない」 | **誤り**。robots.txtにsitemap宣言済みなら発見は可能。GSCの価値は**診断** |
| GSC未登録の断定 | 「ほぼ確定」 | 「外部から観測できる一般的な認証手段は見つからなかった」 |
| 8言語混在の影響 | 「順位だけの問題」 | 品質判断を介し**インデックス選択にも間接影響し得る** |
| `html lang`で言語判定担保 | 担保済みと記述 | **誤り**。Googleは**可視コンテンツ**で判断すると明記 |

hreflang非推奨・クローキングリスク低・エピグラフ修正方針は両者一致でした。
