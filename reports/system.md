# システム開発ターミナル 報告（2026-07-25・第4便）

## ページ実測ツール（page-audit.mjs）を新規作成

司令塔が生HTML（SSR）しか読めず、JavaScript実行後の実際の画面・通信・エラーを見ていないという構造的欠陥を埋める道具として作成しました。

### 使い方

```bash
node scripts/page-audit.mjs --url <URL> [--url <URL2>...] --lang ja,en,zh-cn [--width 1280,390] [--out <dir>]
node scripts/page-audit.mjs --config scripts/audit-configs/sample-3pages.json
node scripts/page-audit.mjs diff <runDirA> <runDirB>
```

### 取得するもの

(a) JS実行後の可視テキスト（`display:none`等を除外） (b) フルページスクリーンショット (c) 実HTTPリクエスト一覧（ステータス・失敗理由付き） (d) コンソールエラー（無加工で全件） (e) **全metaタグを同名でも畳まず全列挙**（今日発覚したog:locale:alternate見落としの再発防止）

保存先は`scratch/page-audit/<URLスラグ>/<日時>_<言語>_<幅>w/`。同一URLの複数回取得が兄弟フォルダに並ぶため`diff`コマンドで比較できます。

### 安全性

GETナビゲーションのみ。クリック・フォーム送信・入力操作は一切行いません。ブラウザコンテキストは取得ごとに使い捨てです。

**ただし正直に書きます**：Codexの指摘どおり、「ツールはサイトに書き込まない」と単純には言い切れません。ツール自身は能動的操作をしませんが、`page.goto()`はページ側のJavaScriptを通常どおり実行させるため、**サイト側コードが発生させる分析通信・Cookie書き込み等まで防ぐものではありません**。これは実際のブラウザで人がページを開いたときと同じ状態で、このツール固有のリスクではありませんが、ドキュメントにこの限界を明記しました。

### 実測して見つけた問題とその場での修正

数ページで動作確認したところ、当初のロジックは**Shopify標準の分析通信（monorail・web-pixelsサンドボックス・Shop Pay等）を大量に誤検知**しました（1ページ19件前後）。ホスト単位の許可リストに絞り込み、修正後は全テストページで誤検知0件になりました。除外件数も`analyticsNoiseCount`として握りつぶさず可視化しています。

`og:locale:alternate`を含む8件のmetaタグが同名でも畳まれず全列挙されることを確認し、日本語版・英語版の`diff`で翻訳の実態を機械的に証明できることも確認しました。

## Codex独立レビュー：高危険度5件を指摘され、その場で修正

「同じ厳しさで見てもらう」というご指示どおり依頼したところ、厳しい指摘が多数返ってきました。

| # | 指摘 | 対応 |
|---|---|---|
| 1 | 「サイトへの書き込みなし」は不正確。サイト側JSの副作用までは防げない | ドキュメントを訂正し限界を明記 |
| 2 | HTTP 404/403/500/503は「通信としては成功」のため検出できていなかった。`httpStatus`変数も未使用のデッドコードだった | `response`イベントでstatus記録・4xx/5xx検出を実装 |
| 3 | 同じ通信が`request`と`requestfailed`の両方で2重カウントされていた。コメント「3回以上」と実装`>1`（2回以上）が不一致だった | Requestオブジェクトで1レコードに集約する方式へ書き換え |
| 4 | `networkidle`が8秒でタイムアウトしても握りつぶし、未完成の画面を「正常」として保存する恐れ | `networkIdleTimedOut`フラグを追加。**実際のテストで`true`が記録され、以前は隠れていた事実が見えるようになった** |
| 5 | 不審判定がURL文字列の部分一致で、無関係ホストまで誤って除外しうる | ホスト名・パスを分解した厳密一致方式に書き換え |

あわせて**finalUrl・リダイレクト検出**と、**diffのmultiset化**（Setベースだと「同じ行が8回→7回に減った」という重複数の変化を見逃す＝皮肉にも当初の目的そのものに穴があった）も実装しました。

残る限界（可視性判定が`opacity:0`等の巧妙な隠しテキストまでは検出できない・モバイル実機のUser-Agent等は再現していない等）は「今後の課題」として正直に記録し、過大な信頼を防ぐようにしています。

## 今後の拡張（設計のみ・未実装）

### (a) 597名の作家ページを8言語で自動巡回

直列実行だと4,776〜9,552パターンで13〜20時間規模になり非現実的です。並列実行・run ID・段階的な絞り込み（まず日本語のみで表示崩れを機械的にふるいにかけ、疑わしいページだけ深掘り）が必要と設計しました。**今回は実装していません**（いきなり全ページを回さないという指示どおり）。

### (b) 本番反映のたびの自動差分確認

スクリーンショットのファイルサイズ差だけでは「意図した変更」と「意図しない変化」を区別できません。構造層（meta多重度）・内容層（見出し等）・通信層（4xx/5xx）・実行層（console error）・視覚層（画素比較）の多層判定にし、意図した変更はレビューでbaseline更新を明示承認する運用が現実的、という設計をCodexの助言も踏まえてまとめました。**こちらも未実装**です。
