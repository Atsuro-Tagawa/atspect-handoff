## 1｜自動返信メール＝代表の操作が必要（実現手順は1枚にしました）

### なぜ自分で作れなかったか（全経路を実測で潰しました）

| 経路 | 可否 | 理由 |
|---|---|---|
| Shopify標準の通知テンプレート | 不可 | お客様通知**57本を全数確認**。お問い合わせフォームの自動返信に相当するものが無い |
| Webhook | 不可 | 設定0件。受け口を作るにも公開HTTPSサーバー（契約）が要る |
| テーマから直接メール送信 | 不可 | 外部送信コード0件 |
| Shopify Flow（無料・Shopify製） | **アプリ未導入** | 導入済みは Subscriptions／Claude API／CLI Connector／Messaging の4本のみ。**インストールに代表のログインが必要** |
| 自動返信アプリ | **アプリ未導入** | 同上。有料の可能性あり |
| Admin APIで下書き注文＋請求書メール | **権限不足** | 現トークンに `write_draft_orders`・`read_customers` が無い |

### ★推奨＝「下書き注文の請求書」（draft_order_invoice）

Shopify標準の通知に既にあり、**実物の本文に「購入手続きを完了する」＝決済リンクが入っている**ことを確認しました。
**アプリ追加も課金も不要**で、決済リンク入りの取引メールを送れるのはこの経路だけです。

さらに、前便でCodexが指摘した「固定リンク1本を全員に配る」ことの弱点が、この方式ならまとめて消えます：

| 固定リンク方式の弱点 | 下書き注文の請求書だと |
|---|---|
| URLの数量を書き換えると66,000円にできる（実測済み） | **金額が注文に固定される。書き換え不可** |
| 同じ人が二重に払える | 支払い済みなら同じリンクからは払えない |
| どの申込に対する33,000円か分からない | **注文に申込者が紐づく** |
| リンク流出で他人が払える | 個別リンクなので流出しても他人には無意味 |
| 受付終了後も古いリンクから払われる | 下書き注文を削除すれば無効 |

**代表にお願いする操作（1回だけ・課金なし）**
1. 管理画面 → 設定 → アプリと販売チャネル → **「Claude API」**
2. APIアクセススコープに **`write_draft_orders`** と **`read_customers`** を追加して保存
3. 「追加しました」とお知らせください

そのあとシステム開発Tが、下書き注文の作成＋請求書送信のスクリプトと、テンプレート文面のあつぺくと化を行います。
**残る限界（正直に）**＝これは「申込したら自動で飛ぶ」ではなく「**受付処理のときに送る**」形です。完全自動にはFlowか自動返信アプリの導入（＝代表のログイン）が要ります。
詳細＝[手順_申込の自動返信メールを実現する_20260731.md](assets/20260801_自動返信と決済リンク/手順_申込の自動返信メールを実現する_20260731.md)

## 2｜情報登録料の商品と決済リンク（完了）

既に稼働中の月額サブスク商品の設定を実測し、**そのまま踏襲**しました。

- ステータス＝**UNLISTED（非公開）**。ACTIVE（全公開）にはしていません
- Online Store のみに公開／コレクション未所属／**ハンドルはランダム12桁**（商品名から推測できません）
- 33,000円（税込）・一回払い・**配送先を聞かない**（`requiresShipping=false`）

### 4経路からの除外＝すべて露出なし（実測）

| 経路 | 結果 |
|---|---|
| `/products.json`（全ページ） | 出ない |
| `sitemap.xml`（子サイトマップ7枚・URL約653件） | 出ない |
| サイト内検索（`/search`＋`suggest.json`・6クエリ） | 出ない（商品結果0件） |
| `/collections/all`＋全コレクション11本 | 出ない |

決済画面まで到達し、**33,000円（内税3,000円）・配送先入力なし**を確認しました（カード番号は入力していません）。
**★確定URLはVaultにのみ記録しました。この報告には転記していません。**

### ★危うく誤報告するところだった件（正直に）

最初の実測で「サイト内検索に出ている」と判定が出ました。**しかしこれは偽陽性でした。**
検索語は canonical リンクと `<title>「◯◯」の検索結果0件</title>` にそのまま反響するため、
「本文に文字列が出たか」で判定すると必ずヒットします。構造（商品リンクと `suggest.json` の結果）で
測り直したところ**商品結果は全クエリ0件**でした。検証スクリプトは修正済みです。
（同種の偽陽性をこの日もう1件踏んでいます＝送信完了の判定に「受付完了」を使ったら、規約第2条の本文に同じ語がありました。**測定は正規表現ではなく構造で行う**、を教訓としてVaultに記録しました。）

### Codexの独立レビュー（1観点＝非公開商品が本当に隠れているか）

**結論＝「通常のサイト回遊からは十分隠れているが、アクセス制御された非公開ではない」**（＝リンクを知れば誰でも買える）。
Codexが挙げた追加経路のうち、こちらで実測できるものは潰しました（推薦API・atomフィード・テーマ由来の商品一覧＝いずれも露出なし）。
潰せないのは**リンクそのものの転送・共有・履歴**で、これは§1の個別リンク方式に移せば解消します。
