# フッター等の小さい文字を墨1色（DeviceGray）にする

作成：あつぺくと制作ターミナル／2026-07-31

Vault実装ログ`_実装ログ_小さい文字の墨1色化_20260731_ATSPECT.md`が正本。

## ★技術的に重要な発見＝「RGBを中性にするだけでは墨1色にならない」

当初は「暖かみのあるグレーを中性グレーにすればK単色になる」と考えたが、**実測で否定された**：

| 色 | ICC変換結果 |
|---|---|
| #6f6a63（現行） | C33 M32 Y37 K40 ← 4色 |
| (107,107,107)（中性にしただけ） | **C23 M20 Y19 K53 ← まだ4色** |

→ **PDFの色空間自体をDeviceGray（`g`演算子）にする必要がある**。CSSの色を変えるだけでは目的を達成できなかった。

## 実施内容（2段階）

1. **CSSを明度を合わせた中性グレーへ**（見た目の濃さを保つ）：`#6f6a63`(明度107)→`#6B6B6B`／`#4a463f`(70)→`#464646`／`#33302b`(48)→`#303030`。
   ★あわせて**記入線`#8a857d`(0.5pt・明度134)→`#868686`**も中性化。文字より細く版ズレの影響が最も出やすい要素のため（指示は文字が対象だが、同じ理由が線にも当てはまるため実施し、ここに明記する）。
2. **新スクリプト`to_device_gray.py`**でPDF内の中性色のRGB指定をDeviceGrayへ書き換え。置換対象は色指定演算子のみでテキスト・座標には触れず、**実行のたびに文字列が変化していないことを自動検証**（全書類OK）。

## 全数調査の結果（8pt前後の文字）

対象＝`#6f6a63`（文書ID AR-F2/AR-K1/AR-P1/AR-P2・株式会社ARTS RESPECT・注記）、`#4a463f`（ラベル・同意リード文）、`#33302b`（弊社記入欄の見出し）の3色。いずれも非中性で4色化する状態だった。**藍・朱の見出し／本文は指示どおり対象外**。

## 結果（実測）

| 書類 | DeviceGray（墨1色） | RGBのまま（有彩色） |
|---|---|---|
| 申込書 | 0, 48, 70, 107, 134, 255 | 藍・背景2色 |
| 規約 | 0, 107, 255 | 背景2色 |
| AR-P1 | 0, 107, 255 | 藍・背景 |
| AR-P2 | 0, 107, 255 | 藍・朱・背景 |

**→ 文字と細線はすべて墨1色。有彩色は意図どおり温存。**

**見た目の変化＝ほぼ無し**：フッター文字の平均濃度は**138.0→134.1（差3.96／0〜255スケール）**。ページ全体の画素差は最大8・平均0.000・**差が5を超える画素は0.004%**。並べた画像でも判別不能（`footer_before_after.png`）。

**A版・B版の両方に反映**：B版は本体が`show_pdf_page`でXObjectに埋め込まれるため、**XObject内の色演算子を直接確認**してDeviceGray保持を検証。さらに**トンボの線自体もDeviceGray化**した（当初はRGB(0,0,0)で描いていた）。

## 検証結果

- 全16ページを画像化して目視＝フッターの濃さは変更前とほぼ同じ・他に変化なし
- `layout_check.py --all`＝**全42項目PASS・FAIL 0件**／`check_doc_text_v3.py`全PASS／`verify_before_print.py`全PASS
- A版・B版の両方に反映を色演算子の抽出で確認

## 実施していないこと・判定していないこと

- **パンフレット（01）＝対象外**。文字がPNGに焼き込まれた**ラスタのため、文字だけを墨1色にすることが原理的にできない**。★パンフ内の小さいグレー文字はCMYK変換時に4色になる見込みで、**選択的な是正には元PNGの作り直しが必要**＝要判断。
- **背景の面（クリーム・青灰）はRGBのまま**（広い面で版ズレの影響がなく、意図した色のため）。
- **藍・朱の見出し／本文**＝指示どおり対象外。
- RGB→CMYK変換そのもの（前便からの継続の要判断事項）。
- 実機のプリンターでの出力確認。
