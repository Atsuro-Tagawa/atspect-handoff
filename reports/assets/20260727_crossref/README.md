# 文書間相互参照の機械照合（2026-07-27・あつぺくとシステム開発）

生データ＝`crossref-findings.csv`（同フォルダ）。ここでは方法・スコープ・Codexレビューで判明した「照合の抜け」をまとめる。

## 対象にしたもの

- **ライブテーマ161（本番・theme id 161141915906）**：全19ページ（Admin API `pages`クエリで取得。公開/非公開すべて含む）と、それぞれのページが使う21セクション（Admin API `themes/{id}/assets.json`で本文を直接取得。ローカルの`atspect-theme`クローンは既知でstale＝一部テンプレートが欠落しているため使用しなかった）。
- **ヘッダー/フッターのナビゲーションメニュー**：GraphQL `menus`クエリで実際のメニュー項目URLを取得（Liquidに直書きされていないため、これを見ないと発見できない）。
- **Shopify組み込みのShop Policies**（Settings > Policies）：GraphQL `shop.shopPolicies`で取得。当初スコープ外だったが、作業中にプライバシーポリシーの内容が重複していることに気づき追加した。
- **物理書類の生成元テキスト**：印刷済みPDF（F02-A/F02-B/F03/AR-P1/AR-P2）そのものではなく、それらの生成元であるVault正本Markdown（`_完成清書_申込書2種と契約規約書_v1.2_20260723_ATSPECT.md`等）をgrepした。

## 主な発見（詳細はCSV参照）

1. **★最重大＝プライバシーポリシー（カスタムページ・Shopify組み込みページの両方）が「作家利用規約第11条の2」を計5箇所で参照しているが、現行規約（全14条構成）にその条文は存在しない。** 内容から見て第7条（掲載情報の保持・公開）を指すべきと推定される。
2. **★重大＝ヘッダーナビゲーション「Exhibitions」が指す`/pages/exhibitions`がHTTP 404。** ページは`published=false`だがテンプレート・セクションはテーマ内に実在し、ナビメニューには残ったまま＝事故の可能性が高い（意図的非公開なら通常ナビからも外す）。
3. **重大＝公開中の`/pages/artist-onboarding-e84exm7hqg`が、存在しない条文（第15条の2）・条数を超える項番（第4条7項）・内容が一致しない条番号（登録料の文脈で第4条＝利用許諾の範囲を引用等）を複数含む。**
4. **中＝未公開の`/pages/artist-materials`・`/pages/artwork-entry`にも同種の壊れた条番号参照が複数あるが、現時点では一般閲覧者はアクセスできない。**
5. **中（意図確認要）＝フッターの「プライバシーポリシー」リンクが、サイト本体の`/pages/privacy`ではなく外部の`https://atspect.co.jp/privacy.html`を指している。** リンク自体は生きている（HTTP200）が、.co.jp→.comの統一プロジェクトから漏れている可能性。

対照として、`atspect-terms-artist.liquid`（全14条）・`atspect-sales-terms.liquid`（全7条）それぞれの自己参照、および両文書間の相互参照（terms-artist第9条↔sales-terms、sales-terms第7条↔terms-artist第13条）はすべて整合していた。また、物理書面側でAR-P1がv1.0→v1.1に改定されても、サイト本文は「版番号を付した別紙」という一般的表現のみで特定バージョンをハードコードしていないため、この版差分による破損は発生していない（安全設計として機能）。

## スコープ外としたもの（意図的な線引き）

- **作家個別ページ・商品個別ページ**（メタオブジェクト由来、597名規模の動的コンテンツ）。静的19ページとは性質が異なり、別系統（`artist-csv-sync.mjs`）の検証対象だが、今回の4種の参照（条番号・文書ID・URL・ファイル名）をそのスクリプトが検査しているわけではない＝**今回の相互参照監査としては未確認のまま**（Codex指摘）。

## Codexレビューで判明した「照合の抜け」（今回は未実施・次回以降の課題）

Codex独立レビュー（`codex exec`）で、今回の方法自体の限界を指摘された。主なもの：

- **最終DOMではなくLiquidソースのみを見た**：条件分岐・CSS・JavaScript・動的データ（section settings・metafield・metaobject）適用後に初めて現れる参照は未確認。
- **多言語判定はクラス名の確認のみ**：`data-lang`以外の言語切替経路、8言語それぞれの実際の表示内容は個別に見ていない（対象3ページが多言語構造を持たないことをクラス名で確認した、という限定的な確認に留まる）。
- **物理PDFのバイナリそのもの（文字列・リンク注釈・QRコード）は見ていない**：PDF生成元のMarkdownソースをgrepしただけ。
- **正規表現の限界**：漢数字の条番号（今回は追加で全文検索し0件を確認）、相対参照（「前条」「次条」等）、範囲参照、動的生成URL・ファイル名は捕捉できない。
- **URL参照の対象が/pages/系に限定**：`/policies/`・`/products/`・`/collections/`・外部リンク全般・`mailto:`・JSON-LD・canonical等は今回チェックしていない。
- **ファイル名参照もAsset一覧との名前一致のみ**：Shopify Files CDN上のPDF・画像、section setting/metafieldのfile reference、大文字小文字やURLエンコードの違いは未確認。
- **layout/theme.liquid・header/footer以外のsnippet・app block・theme app extensionは対象に含めていない**（21セクションという集合が依存関係を閉じているかは未証明）。

これらは「今回の作業が誤っている」というより「機械照合で確実に言えるのは、取得した静的テキストに想定した書式で明記された参照に限られる」という射程の問題。次に同種の監査を行う場合はこの一覧を出発点にできる。

## 証拠

本CSVおよびAdmin APIの生応答（GraphQL/RESTのJSON）は、実行ログとしてこのセッションのローカル一時ファイルに残っているのみで、機密性の高いAPIトークン等は含まれていないが、生JSONそのものの公開は行っていない（CSVへ要約した形のみ公開）。
