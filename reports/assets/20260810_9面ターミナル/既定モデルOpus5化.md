# 9面ターミナルの既定モデルをOpus 5にした（2026-08-10・2便目）

作成＝あつぺくとシステム開発ターミナル

## 実測で確かめた3つの方式（起動引数／設定ファイル／環境変数）

Claude Code CLIで既定モデルを指定する方法は3つとも実在し、いずれも実際に機能することを確認した
（`claude -p "..." --model <値>` の非対話実行で、正しい値では正常応答・存在しない値では
明確なエラーが返ることの両方で検証＝「読んでいるが無視している」ではなく「実際に検証して使っている」ことを確認）。

| 方式 | 実装 | 検証結果 |
|---|---|---|
| **①起動引数** | `claude --model opus`（`--help`に記載あり。エイリアス`opus`/`sonnet`/`fable`か、フルID`claude-opus-5`等） | ◯　正常値でOK応答・不正値で明確なエラー文言。global設定が`sonnet`でも上書きされることを確認 |
| ②設定ファイル | `~/.claude/settings.json` の `"model"` キー（既存で`"model": "sonnet"`が入っていた＝全ターミナル共通の現在の既定） | ◯　既に稼働実績あり（このファイルがSonnet 5既定の実体だった） |
| ③環境変数 | `ANTHROPIC_MODEL`（CLIバイナリの文字列に実在を確認・`ANTHROPIC_DEFAULT_OPUS_MODEL`等の関連変数も存在） | ◯　不正値を入れたところ①と同じエラーが出た＝実際に読まれている |

## 採用した方式＝①起動引数（`--model opus`）

**理由**：
- ②の設定ファイル（`~/.claude/settings.json`）は**全ターミナル共通のグローバル設定**。ここを書き換えると
  9面だけでなく既存の8分割・その他すべてのclaude起動に影響し、代表の「既存の8分割には触らない」指示に反する。
- 9面ランチャーの各ペインはWindows Terminalのプロファイル定義（`settings.json`のプロファイルの`commandline`）で
  `claude`を起動している。**その`commandline`自体に`--model opus`を足す**のが、9面だけに閉じた変更になる。
- エイリアス`opus`（＝現在の最上位Opus。今はOpus 5）を使うことで、将来Opusの世代が上がっても
  再度9プロファイルを編集し直す必要がない。フルID固定（`claude-opus-5`）より運用の手間が少ないと判断。
