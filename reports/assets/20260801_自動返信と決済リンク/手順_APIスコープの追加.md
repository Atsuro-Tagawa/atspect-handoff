# 手順：APIスコープ（`write_draft_orders` / `read_customers`）を追加する

2026-08-01 システム開発T作成。**実際に管理画面を最後まで辿って、画面の実在を確認してから書いています**（推測はありません）。
所要時間の目安＝**代表の操作は約2分**（開く・貼り付ける・押す の3手）。

## 0. なぜ見つからなかったか

代表が開かれた「設定 → アプリと販売チャネル → Claude API」の画面は、**権限の“表示”専用**でした。
実際に確認したところ、その画面にあるのは「アクティビティと権限」の一覧（表示・編集のチェックだけ）と、
右上の「…」＝**「アプリをアンインストール」だけ**で、スコープを足す操作はありません。**代表は正しい場所を見ていましたが、その画面には機能が無いのが正解です。**

さらに「設定 → アプリと販売チャネル → **アプリ開発**」も確認しましたが、こちらは**アプリの一覧ではなくなっており**、
「Dev Dashboardでアプリを開発・管理」という案内カードが出るだけでした。

**スコープの編集は、Shopifyの別サイト「Dev Dashboard」（dev.shopify.com）に移っています。** そこが正しい場所です。

## 1. 代表にお願いする操作（3手・約2分）

### 手順①　次のURLをブラウザで開く

```
https://dev.shopify.com/dashboard/213016489/apps/368527376385/versions/new
```

このURLは「Claude API」アプリの**「バージョンを作成」画面に直接**入ります。
（メニューを辿る必要はありません。★辿る場合は添付画像①②のとおりですが、**同じ名前のアプリが3つ並んでいて紛らわしい**ので、URL直打ちを強くおすすめします。正しいのは「**1 インストール ・ claude-api-6**」の1つだけで、残り2つは「0 インストール」の別物です。）

### 手順②　「APIアクセス」の「スコープ」欄を、下の全文で置き換える

画面を少し下にスクロールすると **「API アクセス」→「スコープ」** という枠があります（添付画像③の赤枠）。
**枠の中をクリック → 全選択（Ctrl+A）→ 下の1行をそのまま貼り付け** てください。

> ★末尾に足すのではなく「全文の貼り替え」にしてあります。欄が横に長くスクロールするため、末尾にカーソルを置くのが難しいためです。

```
read_content,read_files,read_inventory,read_legal_policies,read_metaobject_definitions,read_metaobjects,read_online_store_navigation,read_online_store_pages,read_privacy_settings,read_products,read_publications,read_themes,write_content,write_files,write_inventory,write_legal_policies,write_metaobject_definitions,write_metaobjects,write_online_store_navigation,write_online_store_pages,write_privacy_settings,write_products,write_publications,write_themes,read_customers,write_draft_orders
```

（いま入っている24個はそのまま、末尾に `read_customers` と `write_draft_orders` の2つだけが増えた内容です）

### 手順③　左上の「リリース」を押す

画面の**左上**と**一番下**の2か所に「**リリース**」ボタンがあります（添付画像③の赤枠）。どちらでも同じです。

**そのあと、システム開発Tに「リリースしました」とお知らせください。** 反映確認はこちらで行います。

## 2. ★迷いやすいところ（先回りしてお伝えします）

| 迷いやすい点 | どうすればよいか |
|---|---|
| **同じ名前のアプリが3つ並ぶ** | 「1 インストール ・ claude-api-6」が正解。ほかの2つは「0 インストール」。**URL直打ちなら迷いません** |
| 「構成」という項目を探してしまう | **ありません。**メニューは「モニタリング／ログ／バージョン／設定」の4つで、スコープは**「バージョン」→「バージョンを作成」**の中です |
| 「設定」を開いてしまう | 「設定」には資格情報・連絡先・アイコン等しかなく、**スコープはありません** |
| 「バージョンを作成」＝新しいアプリを作ってしまいそうで不安 | **新しいアプリは作られません。**いまのアプリの設定を1段階新しくするだけです。過去にも同じやり方で3回スコープを足しています（`claude-api-4`＝publications/inventory/files、`claude-api-5`＝legal_policies、`claude-api-6`＝privacy_settings） |
| 「スコープを選択」というリンクがある | 使わなくて大丈夫です。貼り付けのほうが確実です |
| 「任意スコープ」という欄がある | **こちらは空のままにしてください。**上の「スコープ」欄だけ直します |
| ほかの欄（リダイレクトURL／アプリURL／Webhooks APIバージョン／POS／アプリのプロキシ） | **一切さわらないでください。**初期表示のままでリリースして問題ありません |

## 3. 反映されたことの確認

### 代表が確認できる形

リリース後、同じアプリの**「バージョン」画面**（`https://dev.shopify.com/dashboard/213016489/apps/368527376385/versions`）を開くと、
一覧の一番上に **`claude-api-7`** が増えていて、緑の **「有効」** バッジが付いていれば成功です。
（いままで「有効」だった `claude-api-6` からバッジが外れます）

### システム開発Tが確認できる形

こちらでAPIを叩いて、実際にスコープが増えたかを機械で確認します。

```bash
node scripts/check-scopes.mjs read_customers write_draft_orders
```

出力の一覧に **`read_customers`** と **`write_draft_orders`** が並べば反映済みです。

## 4. ★【2026-08-01 追記・実測で判明】リリース後に「もう1クリック」が必要でした

代表が **2026年8月1日 01:09 にリリース済み**です（`claude-api-7`【有効】を確認）。**リリース自体は成功しています。**

ただし、**そのままではアクセストークンに新しい権限が入りませんでした。** 2通りで確認しています：

| 確認方法 | 結果 |
|---|---|
| トークンのスコープ一覧を取得 | 24個のまま。`read_customers`・`write_draft_orders` は**入っていない** |
| 実際にAPIを叩く | 顧客の読み取り・下書き注文の読み取りとも **`Access denied`** |

**理由**＝`.env` のトークンは `shpat_` で始まる「インストール時に発行されるトークン」で、
**権限はインストール（承認）した時点で固定される**ためです。アプリの設定を新しくしただけでは増えません。

### ★あと1回だけ、クリックをお願いします

添付画像 **`手順_承認画面.png`** の画面（タイトル＝**「データアクセスの更新」**）で、**一番下の黒い「更新」ボタン**を1回押してください。
（この画面へのURLは、ターミナルからの連絡とVaultに記載しています。所要＝**約30秒**）

画面に出ている権限は、依頼した2つと**一致していること**を確認済みです：

- 「ストアデータを表示および編集 → お客様の表示：**顧客データ**」＝ `read_customers`
- 「注文の編集：**下書き注文**」＝ `write_draft_orders`

★上部の黄色い「このアプリはレビューされていません」は、Shopifyアプリストアに公開していない自社用アプリのため**通常どおり**の表示です。異常ではありません。

### 押したあと

**「更新しました」とお知らせください。** こちらで `node scripts/check-scopes.mjs` を実行し、
`read_customers` と `write_draft_orders` が入ったかを機械で確認してご報告します。

### ★トークンが新しくなった場合に備えて

「更新」は**再インストールではなく既存インストールの更新**の文言（ボタンが「インストール」ではなく「更新」）ですが、
トークンが差し替わる可能性は残ります。**押したあとにこちらで必ず確認します。** 差し替わっていた場合の影響は次のとおりです。

**★トークンが新しくなった場合、`.env` を差し替えるまで次が止まります（実際にスクリプトを調べた結果）：**

| 止まるもの | 影響 |

## 5. これで何ができるようになるか

この2つの権限が入ると、**作家さまへ「お申し込みを承りました＋決済リンク」のメールを、Shopify標準の
「下書き注文の請求書」で送れる**ようになります。アプリの追加も課金もありません。

あわせて、いまの「全員に同じ固定リンクを配る」方式の弱点（URLの数量を書き換えると66,000円になる・
二重払い・どの申込に対する入金か分からない・リンク流出）が、**個別リンクになることでまとめて解消します**。
