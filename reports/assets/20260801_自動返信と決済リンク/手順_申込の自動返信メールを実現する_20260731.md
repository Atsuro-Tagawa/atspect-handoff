# 手順：申込フォームの自動返信メールを実現する（代表の操作が必要・1枚もの）

2026-07-31 システム開発T。**この作業はシステム開発Tだけでは完了できません。**理由は§1。

---

## 1. なぜ自分で作れなかったか（実測）

| 経路 | 使えるか | 止まっている理由 |
|---|---|---|
| Shopify標準の通知テンプレート | **不可** | お客様通知57本を全数確認したが、お問い合わせフォームの自動返信に相当するものが無い |
| Webhook | **不可** | 設定0件。受け口を作るにも公開HTTPSサーバー（契約）が要る |
| テーマ側から直接メール送信 | **不可** | セクションに外部送信コードは0件。ブラウザから直接メールは送れない |
| Shopify Flow（無料・Shopify製） | **アプリ未インストール** | 導入済みは Subscriptions / Claude API / CLI Connector / Messaging の4本のみ。**インストールに代表のログインが必要** |
| 自動返信アプリ（例：Contact AutoResponder） | **アプリ未インストール** | 同上。有料の可能性もある |
| Admin APIで下書き注文＋請求書メール | **権限不足** | 現トークンのスコープに `write_draft_orders`・`read_customers` が無い（`read_products`/`write_themes` 等はある）。**権限追加に代表の承認が必要** |

→ **どの道を選んでも代表のログインが要る**ため、指示どおり実行せず手順にしました。

---

## 2. 推奨＝「下書き注文の請求書」を使う（★おすすめ）

### なぜこれを勧めるか

Shopify標準の通知に **`draft_order_invoice`（下書き注文の請求書）** があり、実物を確認したところ
本文に **「購入手続きを完了する」＝決済リンク** が入っています。つまり**アプリを増やさずに、
決済リンク入りの取引メールを作家さまへ送れる**のはこの経路だけです。

さらに、前便でCodexが指摘した「固定リンク1本を全員に配る」ことの弱点が、この方式ならまとめて消えます：

| 固定リンク方式の弱点 | 下書き注文の請求書だと |
|---|---|
| URLの数量を書き換えると66,000円にできる（実測済み） | **金額が注文に固定される。書き換え不可** |
| 同じ人が二重に払える | 支払い済みになれば同じリンクからは払えない |
| どの申込に対する33,000円か分からない | **注文に申込者が紐づく** |
| リンクが流出すると誰でも払える | 個別リンクなので流出しても他人には無意味 |
| 受付終了後も古いリンクから払われる | 下書き注文を削除すれば無効になる |

### 代表にお願いする操作（1回だけ）

1. Shopify管理画面 → **設定 → アプリと販売チャネル → 「Claude API」** を開く
2. **APIアクセススコープ**に次の2つを追加して保存する
   - `write_draft_orders`（下書き注文の作成と請求書送信）
   - `read_customers`（申込者の突き合わせ用）
3. 保存後、システム開発Tへ「追加しました」とお知らせください

★アプリのインストールも課金も発生しません。既にあるアプリの権限を広げるだけです。

### そのあとシステム開発Tがやること

- 審査を通過した作家さま1名ぶんの下書き注文（情報登録料33,000円）を作り、請求書メールを送るスクリプトを作る
- `draft_order_invoice` テンプレートの文面を、あつぺくとの言葉に書き換える
  （※現状はShopify初期文面のまま。「配達」「配送」の語が5箇所ある＝配送物が無いので実態と合わない）
- 1名でテストしてから運用に載せる

**残る限界（正直に）**：これは「申込したら自動で飛ぶ」ではなく「**受付処理のときに送る**」形です。
完全自動にするには§3が要ります。ただし、申込は元々1件ずつ人が審査して個別にURLを送る運用なので、
実務上は同じ流れに乗ります。

## 3. 完全自動にしたい場合（どちらも代表のログインが必要）

### 3-A. Shopify Flow を入れる（無料・Shopify製）

1. Shopifyアプリストアで **Shopify Flow** をインストール（代表のログイン）
2. ワークフローを作る：**トリガー＝顧客が作成された** → 条件＝タグに `newsletter` を含む → アクション＝メール送信
3. 申込フォームは `contact[tags]=newsletter` を送っているので、送信のたびに顧客が作られ、これが引き金になります

**★未確認の点**：Flowの「メール送信」アクションが、**社内あて**なのか**お客様あて**なのかは、
インストールしてみないと確認できません（お客様あて送信にはメールマーケティングの購読が条件になる場合があります）。
インストール後にシステム開発Tが確認します。

### 3-B. 自動返信アプリを入れる（有料の可能性あり）

お問い合わせフォームの自動返信に特化したアプリがあります（例：Contact AutoResponder 系）。
差出人名・件名・本文をアプリ側で設定できます。**課金が発生する場合は代表のご判断が要ります。**

## 4. いま作家さまはどうなっているか（暫定の手当ては済んでいます）

自動返信が無いままでも「申し込んだのに手元に何も残らない」状態にならないよう、
**送信完了画面**に次を出すようにしました（2026-07-31 反映済み）：

- ご同意内容の控え（規約の版・本文ハッシュ・同意日時・チェックの内容／印刷・保存ボタンつき）
- **情報登録料 33,000円（税込）の決済ボタン**
- お支払いの確認をもって受付完了となる旨
- お問い合わせ先 `media@atspect.com`

対面でタブレットをお使いの場面では、これだけでその場のお支払いまで完結します。
**メールが無いと困るのは「対面ではない申込者が、画面を閉じたあと」**です。そこが§2・§3で埋まります。
