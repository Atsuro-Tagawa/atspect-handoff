# 作品登録30項目の公開前チェックを機械化した（2026-08-03・あつぺくと制作T 第1便）

モデル＝Opus 5（1M context）。**本番テーマ161への反映はしていない**（触ったのは検査ツールだけ）。
Shopify へは **query のみ**（mutation ゼロ＝データを一切書き換えていない）。

## 1. 何をしたか

`page-audit.mjs` に **`product-check` サブコマンドを新設**し、
Vault `_確定設計_全件検索と内部語解消と登録手順書_20260724_ATSPECT.md` §C の30項目を
**PASS/FAIL まで判定する**ようにした。

★これまでの `page-audit.mjs` は「取ってくるだけ」で、自動で不合格を出すのは
**HTTPの4xx/5xx とコンソールエラーだけ**だった。**判定を入れたのが今回。**

```
node scripts/page-audit.mjs product-check --handle <商品handle>
node scripts/page-audit.mjs product-check --artist <作家handle>   ← 作家1名分をまとめて
```

### 30項目の扱い

| 分類 | 件数 | 扱い |
|---|---|---|
| ① 機械で判定（実装した） | **21** | PASS / FAIL / WARN を出す。FAILは**中身**（どう違うか）も出す |
| ① だが前提が未確定（実装しない） | 3 | `PENDING`＝#9 SKU採番規則／#14 素材語彙表／#15 技法語彙表 |
| ② 人が目で見るしかない | 5 | `MANUAL`＝#1 #11 #12 #20 #26。**代表が上から順に見るだけの1枚**を実データ入りで自動生成 |
| ③ そもそも要らない | 1 | `SKIP`＝#16（§B-3の移行が採否未決） |
| 合計 | **30** | |

**前提が未確定の3項目を実装しなかった理由**＝規則が決まっていないのに判定を書くと、
決まっていない規則がコードの中で既成事実になるため。案は別紙にした（下記3）。

## 2. 実際に1名分で走らせた結果（鈴木 千賀子・作品3点）

### 走らせて初めて分かったこと（3件・すべて是正済み）

| # | 何が起きたか | 本当に直すべきか／判定が厳しすぎるだけか | 対応 |
|---|---|---|---|
| 1 | **#25 が「彫刻」を内部語として不合格にした** | **当方のチェッカーのバグ。** §B-3は「移行後に検索露出してよい語＝作家名13種・**彫刻（product_type）**・木彫等の技法日本語」と明言している＝**ヒットして正常** | 8ジャンル語と語彙表318語の日本語を検査対象から除外した |
| 2 | **#17 が「AR用 ar_*_cm が無い」で不合格** | **判定が厳しすぎる。** 実測＝`ar_*` を持つ商品は**全社で0件**、AR商品自体がDRAFT試作＝**どの作品も満たせない基準**だった | FAIL→**WARN**へ。見逃しにはせず必ず出す |
| 3 | **#18 が「制作年が未設定」で不合格** | **判定が厳しすぎる。** 制作年が資料で確認できない作品は現に存在し、**捏造ゼロでは「分からないなら書かない」が正しい**。不合格にすると推測で年を埋める圧力が生まれる | 未設定＝**WARN**／値の形式違反＝FAIL に分けた |

## 3. 前提が未確定の3項目＝案と数字を出した（決めるのは司令塔）

| 数えた結果 | 値 |
|---|---|

### 決めていただきたいこと（3点）

1. **SKUは案A（`AW-<16進12桁>`）でよいか。**
   根拠＝本番に採番の実例が0件で「既存に合わせる」ことができない。いっぽう**中立な識別子の先例は既にある**
   （`member-d56916fa1bf2` / `reg-7f2fff5a4a1b`＝プレフィックス＋16進12桁）。
   登録順や作家名を含める案（B・C）は、**序列に見える**か**改名時にSKUを変えたくなる**（設計1の防御規則と衝突）。
2. **`custom.material` と `custom.technique` を新設してフィールドを分けるか。**
   ★実測で分かった一番大きいこと＝**`custom.medium` という1つの自由文に、素材（ヒノキ・バルサ）と
   技法（彩色・箔）が混ざって入っている**。**分けない限り #14 と #15 は機械で分離検査できない**
   （分けないなら仕分け表の①→②へ移す必要がある。どちらでもよいが両方は成り立たない）。
3. **語彙表は「閉じた許可リスト」か「推奨＋写像表」か。**
   当方の推奨＝**推奨＋写像表**（作家さまの言葉を殺さず、揺れは写像で吸収＝青銅・bronze→ブロンズ）。

## 4. 代表が見る1枚（②の5項目）

`product-check --artist <作家handle>` で **作家さま1名分の1枚**（`manual-5-artist.md`）が出る。

並びの原則＝**同じ画面で確かめられるものを続けて置く**（画面を行き来させない）。

1. **作家名の表記**（作家さまにつき**1回だけ**。全作品に効く）
2. 作品ごとに **画像（実写か）→ 本文 → 価格**（＝作品ページの同じ1枚で確かめられる順）
3. 最後に **表示崩れ**（PC幅・モバイル幅の画像2枚をまとめて）

判断に必要な実データ（価格・本文全文・代替テキスト・寸法）は**紙に焼き込んである**＝管理画面を開かせない。

★**画像を実際に目で見て気づいたこと**＝スクリーンショットは毎回まっさらなブラウザで撮るため、
**「この言語で表示を続けますか？」の帯が本文に重なって写る**（PC幅・モバイル幅とも）。
崩れではないが、代表が本文を読もうとすると隠れる。**紙に注意書きを入れた。**

## 5. 実施していないこと・判定していないこと

**実施していないこと**
- **本番テーマ161への反映は一切していない**（触ったのは `atspect-system/scripts/page-audit.mjs` のみ）。
- **Shopifyのデータを1件も書き換えていない**（Admin APIは query のみ）。
- **上記 FAIL 8件を直していない**（是正は別の作業。今回はチェッカーを作って走らせるところまで）。
- **#9/#14/#15 を実装していない**（前提未確定のため意図的に見送り。案のみ）。
- **`suzuki-chikako` 以外の作家で走らせていない**（本番の作品が3点＝1作家分しか無いため、そもそも走らせる相手がいない）。
- **Codexの独立レビューを受けていない**（今回は本番反映も対外公開物も無いため、
  「調査・設計段階では呼ばない」という運用方針に従った）。

**判定していないこと**
- **配送プロファイル（#10の一部）**＝現トークンに `read_shipping` が無く `deliveryProfile` が ACCESS_DENIED。
  推測で通さず **UNMEASURED** として出している。管理画面での目視か権限追加が要る。
- **画像の長辺px・容量（#20の一部）**＝**公開品質基準の数値が未確定**（§D-5）。実測値は出すが合否は付けない。
- **「画像が実写か」**＝機械では判定できない。人の目に残した。
- **handleを変更した事実（#21の一部）**＝機械が知り得ないため「リダイレクトが必要なのに無い」は検出できない
  （既存リダイレクトの有無のみ）。
- **Shopify標準検索がSKUを索引するか**＝本番のSKUが0件のため実測できていない。
  案A（ランダム英数字）ならこの未検証は結論を変えないが、案B・Cを採るなら先に実測が要る。
- **検索インデックスの反映遅れ**＝#23〜#25 のFAILは「未反映」の可能性がある
  （設計＝15分→1時間→翌営業日）。今回のFAILはタグが実際に残っていることが原因と特定できているが、
  一般には時間をおいて再実行して確かめる必要がある。
（**既存モードの回帰は実施済み**＝`--url`（`/pages/faq`・ja・1280px）取得成功、`diff`（同URL2回）で
可視テキスト差0行・metaタグ差1行（`shopify-y` のセッションIDのみ＝正常な変動）。既存モードは従来どおり動く。）
