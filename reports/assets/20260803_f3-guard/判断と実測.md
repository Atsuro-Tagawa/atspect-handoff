# 繰-制作-17（個別F3ガードの要否）の判断と実測（2026-08-03・SNS運用T）

## 結論

**`sections/atspect-artwork-entry.liquid` の個別F3ガードは外した。**
**当ターミナル専任2ファイル（`atspect-terms-artist` / `atspect-artist-onboarding`）の個別ガードは外さない。**
**同じ「個別ガード」でも、中身が違い、共通側が覆っている範囲も違うため。**

---

## 1．まず「共通側が何を覆っているか」を読んだ

`assets/atspect.js`（2026-08-02・制作T 第9便）の共通ガードがやっているのは**1つだけ**：

> `invalid` が起きた瞬間に `html` の `scroll-behavior` を `auto` にし、**700ミリ秒後に
> インライン指定を削除する**（`removeProperty`）。

**「どこへ移動するか」は決めていない**＝ブラウザ標準の `scrollIntoView` に任せている。

## 2．artwork-entry の個別ガードは、共通側と**同じことしかしていなかった**

外した塊（1,417バイト）の中身：

```js
document.addEventListener('invalid', function(){
  if (guard) return; guard = true;
  var de = document.documentElement, prev = de.style.scrollBehavior;
  de.style.scrollBehavior = 'auto';
  setTimeout(function(){ de.style.scrollBehavior = prev; guard = false; }, 600);
}, true);
```

移動先の指定（`block:'center'` 等）も、独自の検証文言も無い。**共通側と完全に同じ役割。**

## 3．★消す前に実測した（制作Tの「取り消すと不具合が戻る」は成り立たなかった）

繰-制作-17に「取り消すと不具合が戻るため残置している」とあったため、**本番を触る前に**、
配信物のHTMLから個別ガードの`<script>`だけを取り除いた版をブラウザへ差し替えて（route差し替え）比べた。

| 押してからの時間 | ①現状（二重） | ②個別ガードを外した版 |
|---|---|---|
| +100ms | **移動2,432px 完了** | **移動2,477px 完了** |
| +300ms | 同じ位置 | 同じ位置 |
| +600ms | inline指定＝**消えた**（個別側の後片付け） | inline指定＝`auto` のまま |
| +700ms | 消えたまま | inline指定＝**消えた**（共通側の後片付け） |
| +3,000ms | 消えたまま | 消えたまま |

→ **どちらも100ミリ秒以内に移動が完了し、後片付けも済む。** 個別ガードを外しても挙動は変わらない。
　（600ms／700msの差が、どちらのガードが後片付けしたかの見分けになっている。）

## 4．二重に持ちたくない理由（外した積極的な理由）

- 個別側は「**元の値を覚えて600ms後に書き戻す**」、共通側は「**700ms後にインライン指定を削除する**」。
- 無事に済んでいるのは **600 < 700 という時間の前後関係**に依存しているだけ。
- 共通側のコメントには「値を覚えて書き戻す方式だと、個別ページ側の同種ガードと二重に走ったとき
  `auto` が最後に残り、そのページだけ smooth が恒久的に消える事故になりうる」と、
  **まさにこの危険が名指しで書かれている**。共通側が700msにしているのはその回避策。
- **この前提は artwork-entry 側のどこにも書かれていない。** 将来だれかが共通側の700msを縮めると、
  このページだけ静かに壊れる。→ **重複をなくして依存を断つほうが安全**と判断した。

liquid内にも「消さないこと」とコメントを残した。

### ★第1段階の登録フォームで「中央に置く処理」が動いていない理由（特定できた）

コードは存在するが、**置かれている場所が違う**。

- しかしこのフォームには **`novalidate` が無い**（制作T自身がコメントに明記している）。
  → **ブラウザのネイティブ検証が先に走り、`submit` イベントは発火しない。**
  → **`jumpInto` は一度も呼ばれない。** 書かれているのに届かない場所にある。

**当ターミナルの2ファイルが効いているのは、`scrollIntoView({block:'center'})` を
`submit` ではなく `invalid` の中に置いたから**（2026-08-01 第8便）。**この置き場所の違いが分かれ目。**

→ **第6節の結論（当T専任2ファイルの個別ガードは外さない）は変わらない。**
