## 5. ★検知語の申し送り＝`entre` の誤検知（次のセッションで直すこと）

第26便で片山東熊さまの略歴の**現在形** `il entre au ministère` を捕まえるため、
仏語の検知語に **`entre`** と **`achève`** を足しました。ところが第27便で
`la relation **entre** les choses et l'espace`（「もののあいだの関係」）の**前置詞**に当たり、
**残存2件という誤った数字**を出しました（実際の残存は0件）。

**直し方＝語だけで当てず、前後を見る。** `entre` は
「主語（il/elle）＋ `entre` ＋ 前置詞（au/dans/à）」の並びのときだけ動詞とみなす、といった条件が要ります。
`achève` も同様（`s'achève` は自動詞用法で別）。

**★この件は、より大きな恒久ルールの一例です（下記6の2番目）。**

## 6. 恒久ルール（このターミナルの運転規則）

1. **翻訳Tは常時運転する（待機しない）。** 指示の切れ目では、日課の次の束へ自分から進む。
2. **★機械の当たりを、そのまま是正対象の件数として報告しない。** 本日3回、当たり件数と誤り件数が食い違いました。
   - 独語 `Bildhauerei` ＝当たり**74欄**／誤り**4欄**
   - 中国語の中黒 `·` ＝当たり**57件**／誤り**0件**（`厄内斯特·费诺罗萨` 等、**外国人名の区切りとして正しい**用法だった）
   - 仏語の残存 ＝当たり**2件**／誤り**0件**（前置詞 `entre`）
   ★必ず**当たった箇所を1件ずつ読んでから**件数を確定する。
3. **★冠詞の性と、人の性別を混同しない。** `personne` / `Person` / `Persönlichkeit` は文法上は女性名詞だが、
   その人が男性なら代名詞は `Il` / `Er`。第13便でこれを取り違え、3欄で男性の方に女性の代名詞を当てました（第25便で是正・現在0件）。
4. **束・工程ごとにpushする。** 最後にまとめてpushしない（到達点が常に残る形）。
5. **git規律**＝`check-ignore` → `add` と `commit -m "..." -- <同じ明示パス>` を1コマンド連続 → `show --name-only` 全読 → push。
   `git add .` / `-A` は使わない。記録は **`.md`**（`.json` は司令塔から見えない）。
6. **★Codexは使用可能。**（8/9夜にリセット済み。本日 第26便5分29秒・第27便4分37秒で70依頼が完走）
   ★**古い上限情報を書き写さない。** 前回の引き継ぎ書には「8/16まで使えない」とあったが、実測したら使えました。
   **予測された日付を信じず、毎回まず1回投げて実測する。**
7. **Codexへの渡し方**＝1依頼＝1ファイル・1観点。PDFのバイナリや画像は渡さない。
8. **他ターミナルのファイル・他ウィンドウへのキー送信に触れない。**
   `atspect-system` は他ターミナルと共有のローカルリポジトリ（remote無し）。**自分の `honyaku*` 以外は触らない。**
9. **本番データを書き換える直前に、必ずライブを取り直す**（`plan` と `apply` の間に他ターミナルが入りうる）。
10. **`apply` の出力を `grep -c` 等に通さない**（出力を食われて成否が読めず、二重実行の原因になる。本日1回発生し、CASが書き込み前に止めた）。
