# 関所手順書＝新規作家さまの翻訳を「公開前に」通す一連の手順（1枚）

2026-08-09・あつぺくと翻訳品質T（Fable 5）作成。**リサーチT・司令塔が新規作家の便にそのまま貼れる形。**
目的＝新規分から「公開後の磨き直し」という工程自体を無くす。**公開前に関所を通す。**

---

## 手順（原稿確定 → 公開 の間に挟む。全体で1名あたり10分前後）

**前提**＝日本語原稿は確定済み（atspect-artist-profile-writing／捏造ゼロ検証済み）。

### 1. 生成の前に読ませるもの（翻訳を作るセッションに渡す3点）
- 文体基準＝`atspect-handoff/reports/assets/20260808_翻訳品質_第1便/文体基準_7言語.md`
  （敬体/常体の3層・言語別の禁止・用字・寸法表記。★訳はこの基準に合う形で**最初から**生成する）
- 台帳3点＝`kanshou_dict.json`（呼称）／`de_term_ledger.json`（独語術語）／`genre_labels_i18n.json`（ジャンル）
  **台帳にある語は台帳の形以外で訳さない。**
- 裁定辞書＝`atspect-system/scripts/honyaku-ruling-dict.json`
  （とくに (b)自動棄却の9型＝**やってはいけない直し**の一覧として読む：固有名詞をいじらない・
  併記形を崩さない・本人の比喩を平板化しない・素材語を具体化しない）

### 2. 生成時の必須ルール（文体基準の要点＝7つだけ）
1. 略歴=三人称・叙述体／本人のことば=一人称・敬体。**層を混ぜない**
2. 固有名詞＝**読みが一次資料で確認できない人名はローマ字化せず原文のまま**（読みは推測しない）
3. 定訳のない日本固有語＝ローマ字＋その言語での短い説明。原題・原名は残す（`訳名（原名; ローマ字）`）
4. 序列語を訳で足さない・強めない（「知られる」を renowned にしない）
5. 仏語＝複合過去（単純過去を使わない）／韓国語＝略歴は해라体・本人のことばは합니다体
6. 中国語＝簡体・繁体を**別々に**推敲（機械変換で済ませない）。かな・中黒・全角空白を残さない
7. 功績欄の1文目は**主語と動詞のある完全文**にする（日本語のみ体言止め可）。1文を詰め込みすぎない（目安＝zh/ko/ja 100字・欧文220字以内）

### 3. 機械の関所（2分）
```
node scripts/honyaku-scan.mjs --handle <handle>        # 用字の型＝未判定0を確認
node scripts/_readonly-honyaku-kata-20260809.mjs       # 型1・型2に入っていないか（該当handleの行だけ見る）
```
序列語の当たりが出たら**公開前にリサーチT基準（作家本人への序列語は不可）で判定**する。

### 4. Codexの関所（差分検品・5分）
`drive2.sh` の依頼文（差分方式）で7言語を検品＝**文体基準の違反だけを修正文つきで**出させる。
出た指摘を裁定辞書で3分類 →（a)は反映（b)は棄却（c)は人が判定。
**違反0〜数件が正常。** 10件を超えるなら生成時に基準が効いていない＝手順1に戻る。

### 5. 反映と検証（3分）
- 反映は `artist-i18n-update.mjs` の plan→apply（バックアップ・楽観ロック・読み戻し検証つき）
- 反映後＝`honyaku-scan.mjs --handle` で**序列語増分0・未判定0**を実測
- **実画面を最低1言語（de推奨＝破綻検知の基準言語）撮って目で見る**（泣き別れ・横溢れ）

### 6. 記録（1分）
判定台帳（`honyaku-allowlist.json`）に「誤りではない」と判定した箇所を理由つきで登録。
(c)で判定した結果が新しい型なら、裁定辞書に追記して翻訳品質Tへ申し送る。

- 読み未確認の人名のローマ字化／台帳と違う訳語
- 「一覧で0件だった」だけの確認（★名指しでもう一度確かめる＝恒久ルール）
