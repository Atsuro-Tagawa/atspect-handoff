# 翻訳検品（あつぺくと作家ページ）

**対象＝作家625名の、日本語以外7言語（en / zh_cn / zh_tw / ko / fr / es / de）の訳文。**
**触ってよい欄＝略歴(bio)／一言紹介(statement)／功績(viewpoint)／所属団体(groups)。**
代表作欄・現存作家は**触らない**（下記6）。

★**言語キーはアンダースコア**（`zh_cn` / `zh_tw`）。`zh-cn` とハイフンで書くと**無言で0件**になる。
0件が出たら、生JSONの素の出現数と突き合わせて「無い」のか「見えていない」のかを確かめる。

---

## 1. 二重検品（司令塔裁定・恒久）

**同じ訳文・同じ日本語原文のまま、順序だけを変えて2回**検品する。

| | 1回目 | 2回目 |
|---|---|---|
| 欄の並び | 一言紹介 → 略歴 → 功績 → 所属団体 | **逆順** |
| 観点の並び | (1)事実の追加 …(5)訳語の不統一 | **逆順** |

```
node scripts/_readonly-honyaku-bin-prompts2-20260812.mjs <出力先> fwd <handle…>
node scripts/_readonly-honyaku-bin-prompts2-20260812.mjs <出力先> rev <handle…>
```
1名×1言語＝1依頼。10名なら **70本×2＝140本**。24本ずつ並列で回すと2回で**約4〜5分**。

**司令塔が定めた条件4つ（変えない）**
1. **2回目を「1回目が指摘した欄だけ」に絞らない。** 絞ると取りこぼす。
2. **一致した指摘ほど疑い、原文照合を省かない。**
3. **一致率の数字は追わない。** 引用の取り方に左右され、実務の判断に使えない。
4. **別のモデルへの切り替えは司令塔が別途設計する。勝手に切り替えない。**

★**どちらの回が当たりを引くかは束ごとに入れ替わる**（実測＝第18束は2回目44%、第20束は1回目55%）。
**片方に決め打ちできない。**

### 回答の取り出し方（★数え間違いに注意）
`codex exec` の出力は「依頼文の反響 → 回答 → tokens used → 回答の再掲」の順。**回答部分だけ**を取る。
```
awk '/^codex$/{f=1;next} /^tokens used$/{f=0} f' <ファイル>
```
★`grep "指摘なし"` で数えると、**依頼文そのものにその語が入っている**ため全件に当たる（実際にやった）。

## 2. ★当たり件数は、誤り件数ではない

**機械の当たり・検品の指摘は「疑い」であって「誤り」ではない。1件ずつ日本語原文と突き合わせてから件数を確定する。**

実測した食い違いの例：

| 場面 | 当たり | 実際の誤り |
|---|---|---|
| 戦争名（第二次世界大戦） | 20名超 | **1名**（原文が「太平洋戦争」なのは1名だけ。他は原文も第二次世界大戦） |
| 文の分割の壊れ | 97件 | **0件**（正しい独語の日付・世代名の序数・`Co., Ltd.`・中国語の `与其…不如…`） |
| 独語 `Bildhauerei` | 92文 | **53文**（40文は正しい独語で、直せば壊していた） |
| Codexの検品（1束） | 70本すべてに指摘・221件 | **47件** |

### 原文を見ないと逆向きに壊す実例
- 原文が「金を加えた染付**など**」→ 訳の `and other means` は**正しい**（「など」は原文にある）
- 原文が「**一人**とされる」→ 訳の「〜の一人」は**正しい**（一律に消してはいけない）
- 原文が「**戦後**」→ 訳の「第二次世界大戦後」は**正しい**（日本語の戦後はWWII後を指す）

## 3. ★一致した指摘ほど疑う（条件②）

**同じモデルが2回同じことを言っても、独立した2つの証拠ではない。**
一致が示すのは「正しさ」ではなく「**その判定が安定していること**」だけ。

### 反例（必ず読むこと）＝両回が一致して間違えた実例

北野恒富さまの功績欄「鏡や**籠**などの持ち物」について、**両方の回が「籠＝かご(basket)の誤訳だ」と指摘した。**
**これは誤指摘だった。**

> 同じ略歴に代表作 **《宝恵籠》（ほえかご）** が挙がっている。宝恵籠は大阪・今宮戎の**駕籠**であり、
> 現行の `palanquin` ／ `Sänfte` ／ `가마` はいずれも**正しい**。韓国語の略歴も《**호에카고**》と書いている。

**一致を根拠に採用していたら、5言語を壊していた。**
→ **一致した指摘でも、必ず同じページの他の欄（略歴の作品名など）と突き合わせる。**

## 4. ★採用前に、置換後の文を再検品する（工程として省かない）

置換元がちょうど1回一致しても、**置換後の文が自然とはかぎらない。**
是正表ができたら、**言語ごとに「旧→新」を並べてネイティブ視点で再検品**させる。

実測＝毎束6〜13件の×が出て、**ライブに入る前に直せている**。

### ★ただし、再検品の案をそのまま採らない
**再検品は「直す」ためではなく「確かめる」ために使う。** 提案が原文から離れることがある。

実例（いずれも原文を示して問い直し、こちらの判断が支持された）：

| 提案 | 何が問題か |
|---|---|
| 「亲近（親しく）」→「**热爱**（愛する）」 | 原文は「親しく」。強すぎる |
| 「素色（**無地**）」→「**素樸**（素朴）」 | 原文は「無地のように見えて」。素樸は作風の素朴さで別の意味 |
| 「染付」→「**青花**」 | 同じページの功績欄は「染付」のまま＝**用語が割れる** |
| 一言紹介に「**技法**」を足す | 原文の一言紹介に「技法」は無い（略歴にはある） |
| 「誰にでも分かる」を落とす書き換え | **原文にある事実を消す** |

★**「それは原文にある事実なので落とせない」と条件を付けて問い直す。**

## 5. 裁定辞書の参照（54型）

**正本＝`C:\Users\ataga\atspect-system\scripts\honyaku-ruling-dict.json`**
（`atspect-system` は remote 未設定のローカル。**司令塔からは見えない**ので、区切りごとに写しを `-handoff` の assets へ置く）

3分類：
- **auto_adopt**＝自動採用してよい型（中黒・全角約物・型1・文法の明白な誤り・引用符・文分割の壊れ ほか）
- **auto_reject**＝**指摘されても採らない型**。とくに効くのが次の2つ：
  - **B10＝故人に現在形を過去形にせよという指摘。** 625名すべて同じ書き方なので、**1名だけ直すとサイトが割れる。**（1束で約60件を不採用にしている）
  - **B1＝固有名詞・館名・賞名の表記／ローマ字／長音記号。** 正式名の確認が要る＝事実の断定。
- **human**＝必ず人が判定する型（序列語・限定の増減・事実・機関名の訳語 ほか）

**★各規則の `counter_examples`（反例）が本文である。** 反例に当たるかの確認までが「自動」の中身。

### 型は言語ごとに絞って渡す
その言語に効く型だけを出すには **`atspect-term-inject` スキル**を使う（全部渡さない）。

## 6. 触らないもの

| 対象 | 理由 |
|---|---|
| **代表作欄** | 別便で個別に指示される |
| **現存作家** | 文体基準が未設計 |
| **横断型（1名だけ直すと割れるもの）** | 例＝中国語の肩書き「西洋画家／西画家」の割れ、人間国宝の独語が3通り。**実測して記録し、横断の専用便で決める** |
| **日本語の原文** | 別の持ち場 |

## 7. 1束の流れ

1. `_readonly-honyaku-nikka-20260810.mjs <カーソル> 10` で次の10名を出す
2. `_readonly-honyaku-bin-prompts2-20260812.mjs <出力先> fwd|rev <10名>` で 70本×2 を作る
3. 24本ずつ並列で `codex exec --skip-git-repo-check - < q…`
4. 回答部分だけを取り出して集約（上記1の awk）
5. **両回を突き合わせ、日本語原文と照合して採否を決める**（辞書の型で仕分け）
6. 是正表 → `honyaku-patch-build.mjs` → **置換後の文を再検品** → 直す
7. `plan` → `apply` → **ライブで反映を再確認** → 記録して push（**書き込みは atspect-write-safety に従う**）
8. 記録には「その是正をどちらの回が拾ったか」を必ず残す（1/2/両方）

## 8. 報告に必ず書くこと

- 通読累計（◯名／625名）と次のカーソル
