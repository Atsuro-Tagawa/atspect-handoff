## 2｜判断2＝審査経由フォームの同意を「契約規約書」の1つに集約した

**変更前＝必須チェック4つ**（規約確認表明／規約同意／料金同意／表明保証確認）
**変更後＝必須チェック2つ**（**確認の記録**＝規約確認表明／**ご同意**＝契約規約書の1つ）

- 削除＝`11_料金同意` と `12_表明保証確認`。
- 代わりに1行を置いた（画像 `05_…png`）：
  > 上の「契約規約書」には、費用についての定め（第8条。金額等は別紙「料金のご案内」によります）と、
  > 出品される作品についての保証（第5条）が含まれます。上のご同意は、これらを含むすべての条項へのご同意です。
- **条番号は反映時点のライブの規約本文で確認した**（第5条＝作家さまによる保証／第8条＝料金）。
- ★**規約本文は1文字も変えていない**（下記4）。

★**「ご同意」のチェックは契約規約書の1つだけになった。**「確認の記録」の読了表明は、対面用の申込書と
同じ扱いで残している（**同意ではなく、規約を最後まで読んだという記録**。画面には規約全文が載っており、
最後までスクロールするまでチェックできない仕組みのため）。**これも外すご判断なら1行で外せる。**

## 3｜判断3＝規約ページ（公開）から申込フォームを外した

**変更前**＝公開の規約ページに、第2段階と同じ申込書フォーム（入力欄25・必須チェック・送信ボタン）が載っていた。
**変更後**＝**規約全文だけの「読む書類」**になった。実測＝

| 項目 | 変更前 | 変更後 |
|---|---|---|
| 申込フォーム | あり | **なし**（残るのはサイト共通のフッターのメール登録のみ） |
| 入力欄 | 25 | **0** |
| 同意チェック | 2 | **0** |
| 送信ボタン | あり | **なし** |
| 規約全文（第1条〜第14条） | あり | **あり**（欠落なし） |

★**実装＝規約全文の markup を1本にまとめ（Liquidの capture）、対面用の申込書ではフォームの中に、
規約ページではフォームを作らずそのまま描画する形にした。markupを複製していないので、
片方だけ古くなる事故が構造的に起きない**（推薦フォームと同じ考え方）。

### ★あわせて直した1件（指示外・理由あり）

**規約ページなのに、規約全文が高さ58vhの入れ子スクロール枠に閉じ込められていた**（`03_…png`）。
この枠は申込書側の「最後まで読むまでチェックできない」仕組みのためのもので、**チェック欄の無い
規約ページでは働かない**。読む書類として素直にページに流した（`04_…png`）。
実測＝ページの高さ 2,436px →**7,610px**／入れ子スクロール**なし**／横スクロール**なし**。
★**申込書側の枠はそのまま**（読了ゲートは正常動作を再確認）。
