## 3. ★なぜ食い違いが生まれたのか（工程を調べた）

**原因は仕組みにある。作家データを書き込む経路が2本あり、片方が artist_i18n を書かない。**

| 経路 | 書く先 | 結果 |
|---|---|---|
| **`artist-csv-sync.mjs apply`**（CSV正本 → ライブ） | **個別フィールドだけ**。`artist_i18n` は**設計として明示的に除外**されている（同スクリプトの冒頭コメント＝「JSON内サブキーのため別途設計が要る」） | **通すたびに片側だけ新しくなる** |
| `artist-i18n-update.mjs apply`（指示書 → ライブ） | `artist_i18n` **と**個別フィールドを1回の更新で**同時に**書く | 食い違わない |

つまり、**CSVを直してから `artist-csv-sync` で反映した作業はすべて、artist_i18n を置き去りにしてきた。**
実際、食い違っていた16名の日本語欄はすべてCSVと一致しており、**CSV→ライブの経路で入った変更**であることが裏づけられる。

★**画面がどう見えるか**＝テーマはSSRで個別フィールドを描画し、そのあとJSが `artist_i18n` で上書きする。**食い違うと「最初に見えた文が別の文に置き換わる」**、あるいは言語によって別の本文が出る。

### 再発を防ぐ運用（1行）

> **CSV正本を直したら `artist-csv-sync apply` ではなく `artist-i18n-update.mjs` で反映する（後者だけが2か所を同時に書く）。当面は `artist-csv-sync apply` を使わない。**

★補足＝根本的には `artist-csv-sync.mjs` の `apply` に「artist_i18n も同時に書く」か「食い違いを作る前に止める」実装を入れるのが正しい。**スクリプトの改修はシステム開発Tの持ち場**のため、本便では提案にとどめる。
