## ★はじめに｜前回の洗い出しB表の数値を訂正します

**洗い出し.md のB表は、CSSの「宣言値」であって、画面で実際に効いている値ではありませんでした。**
今回ブラウザの計算後の値（computed style）で測り直したところ、次のとおり食い違っていました。

| 役割（第1段階） | 洗い出しB表 | **ブラウザ実測（是正前）** | 判定 |
|---|---|---|---|
| 入力欄 | 14px | **16px** | すでに目標どおり |
| 自由記入欄 | 14px | **要素が存在しない**（DOMに0件） | 対象なし |
| ラジオ | 13px | **14px** | 要是正 → 16pxにした |
| 「必須」バッジ | 10px | **12px** | すでに目標どおり |

**原因**＝共有CSS `assets/atspect.css` に、次の `!important` の底上げ規則が既に置かれていました。

```
.atspect-areg__input, .atspect-areg__textarea, .atspect-areg__select{ font-size:16px !important; }
.atspect-areg__req, .atspect-areg__opt{ font-size:1.2rem !important; }
.atspect-areg__radio{ font-size:1.4rem !important; }
```

セクション側の宣言（1.4rem／1.0rem／1.3rem）はこれに負けており、**画面には出ていませんでした。**
裏づけ＝セクション内に制作Tが2026-08-01に書き残したコメント「※上のfont-size/colorの宣言は別の規則に
上書きされている（実測＝12px…）」があり、この上書きは前回の洗い出しより前から存在していました。

→ **結論：iOSが入力時に自動でズームする問題（洗い出しC-1）は、すでに起きていませんでした。**
　（★ただし当方は実機を持たないため、実際のiPhoneでの挙動は確認していません。）

→ **恒久の学び：文字の大きさは宣言値ではなく計算後の値（computed style）で測る。**
　`!important` の底上げが別ファイルにあると、ソースを読んだだけでは実効値が分からない。
