## 作業D．禁止値チェックのフックを作りました（設計5点をすべて満たす）

| 設計 | 実装 | 実測 |
|---|---|---|
| ①一覧はローカル（Vault）に置き、リポジトリに置かない | 非公開の一覧を新設 | リポジトリ側に一覧は無い |
| ②読めないときは素通しでなく止める | 一覧が無い・壊れている・形が違う → **停止** | **一覧を一時的に外して実測＝止まった** |
| ③値だけでなく同じ性質の文字列も止める | 「形」による判定（**形の定義も一覧の中＝ここには書きません**） | **実在しないダミーでも止まった** |
| ④伏せ字への置き換えを標準の逃げ道に | 止めたときに**伏せ字の書き方を画面に並べる**。伏せ字自体は検出しない | **伏せ字だけのコミットは通った** |
| ⑤識別子を替えたら一覧も同時に直す | **手順書に書くだけでなく、差し替えの道具が自動で一覧へ足す**（足せなければ警告して停止） | 本日の新旧6件が一覧に入っていることを確認 |

**入れた場所**＝`atspect-handoff` と `atspect-system` の
**pre-commit（これからコミットする足す行）／pre-push（これから押し出す足す行）／commit-msg（コミットの文言）**。
**6つとも入っていることを確認済み。**

### 実測（★ダミーは1件もpushしていません）

| 試験 | 結果 |
|---|---|
| 一覧の値を含むダミーをコミット | **止まった**（コミットは作られていない） |
| 形だけ同じダミー（実在しない値）をコミット | **止まった** |
| 伏せ字にしたダミーをコミット | **通った** |
| 一覧を読めなくして走らせる | **止まった** |
| 禁止値入りのコミットを（検査を外して）作り、pushの入口で調べる | **止まった（1箇所を正しく指摘）** |
| 問題のない差分でpushの入口を調べる | **通った** |
| **コミットの文言に禁止値を入れてコミット** | **止まった**（★Codexの指摘で気づいて足した口） |
| 後始末 | **ダミーとダミーのコミットを消し、HEADと未push件数が元どおりであることを確認** |

### ★作った道具の重大な誤りを2件、自分で見つけて直しました

1. **判定の形が広すぎた**＝最初に入れた形が、**コミットのSHAやファイルのハッシュにも当たり、
   既存の記録だけで464箇所**が引っかかりました。このままでは**毎回止まって、道具ごと外されます**。
   → **当たる場所を限定**し、**「この形をこれ以上広げないこと」を一覧の中に書き残しました**。
2. **pushの入口で、範囲を受け取れていなかった**＝標準入力の読み方を誤り、
   **常に「比べる相手が無い」側に落ちて全ファイルを見ていました**（＝過去の記録で毎回止まる）。
   → 読み方を直し、**押し出す差分だけを見ることを実測で確認**（1箇所だけを正しく指摘）。

★**見るのは「これから足す行」だけ**にしました。過去の記録は**裁定どおり書き換えない**ため、
全部を見ると毎回止まり、道具が使われなくなるからです。
**過去分の棚卸しは、手で走らせる別の口を用意しました**（本日の実測＝111箇所）。

★**正直に**＝`--no-verify` を付ければこの検査は迂回できます。
**フックは「うっかり」を止める仕組みであって、意図的な回避は止められません。**
