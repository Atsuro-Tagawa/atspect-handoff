## 1. どこに置くか（ホスティング）— ★両案併記・司令塔判断待ち

### 案A：小さな専用サーバーを1台借りて、そこに全部載せる（VPS）

- 例＝Xserver VPS（既にXserverと契約があるため管理画面が同系で分かりやすい）または さくらのVPS。
- **月額の目安＝1,540〜1,980円（Xserver VPS 2GBプラン・税込）**。
  ★2026-08-06にWeb検索で確認した公表価格＝12か月契約1,540円/月・1か月契約1,980円/月。
  **2026-09-01に料金改定（値上げ）の告知あり**。他社（さくら等）はより安い場合があるが**未確認**。契約前に最新価格を必ず見る。
- ダッシュボード本体（Node.js）・メール読み取り（IMAP）・Shopify読み取り・
  スプレッドシート連携・AI要約の呼び出しを**1か所**で動かす。
- 良い点＝**メールのIMAP読み取りに制約が無い**（常時動くサーバーが必要な処理はこれが素直）。
  1か所なので秘密情報（.env）の置き場も1つ。
- 弱い点＝サーバーの面倒（OS更新等）を見る人が要る（→実装を担うOpusターミナルの運用手順書で補う）。

### 案B：Googleスプレッドシートを正本にして、画面は薄く（サーバーレス寄り）

- 台帳・名言集・お金の予定表＝スプレッドシートそのもの。
  画面＝Cloudflare Pages（無料）＋小さな関数（Workers・無料枠内）。
- **月額の目安＝0円**（無料枠内。超えても数百円）。
- 良い点＝第1段が速い・落ちても「スプレッドシートを直接開く」への逃げ道が最短。
- 弱い点＝**第2段のメール読み取り（IMAP）はWorkersでは素直に動かない**ため、
  結局第2段で小さなサーバー（案A相当）が要る。

### ★推し（判断材料として・確定は司令塔）

**第1段は案Bの形で速く出し、第2段（メール統合）の着工時に案Aのサーバーを足す**、の段階併用。
理由＝第1段の価値（今日やること・台帳）はサーバー無しで出せる／メールは実測待ち（待3）が
解けてからサーバーを立てる方が、作り直しが無い。
**ただし「最初から案Aで1か所にまとめる方が管理が単純」という考え方も成り立つ**ため、両案とも残す。

## 2. 何で作るか

| 部品 | 提案 | 理由 |
|---|---|---|
| 画面 | HTML＋最小限のJavaScript（フレームワークを使うなら軽いもの1つに固定） | 初心者向けの単純な画面に大掛かりな道具は不要。**実装Tの得意に合わせて選定してよい**（画面設計の文言・配置は `02_画面設計.md` が正） |
| 台帳・名言集・お金の予定表 | Googleスプレッドシート（API経由で読み書き） | 逃げ道の保証（直接開ける）・バックアップ（版履歴）・4人が既に使える |
| メール読み取り | IMAP（3アカウントとも**IMAPであることは2026-08-01実測済み**） | 実体を動かさず読むだけにできる。★フォルダ構成・通数＝実測待ち（待3） |
| 注文読み取り | Shopify Admin API（読み取り権限のみのトークンを新規発行） | **書き込み権限を持たせない**＝ダッシュボード経由でShopifyを壊せない形にする |
| AI要約・返信下書き | Claude API | 費用は通数次第＝**★仮置きで月数百〜数千円**。待3（1日の通数）が分かれば確定できる |
| 来歴カード・書類の出力（第3段） | 既存の雛形（HTML→PDF）を流用 | 紙の書類群で使っている生成の型を流用できる |

## 3. ログイン（鍵）— ★両案併記・司令塔判断待ち

**共通の前提＝4人それぞれに別の鍵**（共有アカウントにしない）。理由＝「誰が何をしたかの記録」が
確定要件にあり、共有だと記録が取れない。

### 案ア：メールに届く6桁の数字を入れる方式（パスワードを覚えない）

- 「はじめる」を押す→自分のメール宛に6桁の数字が届く→入れる→開く。
- 良い点＝**覚えるものが無い**。パスワード忘れ・メモ書き事故が構造的に起きない。
- 弱い点＝メールが開ける状態でないと入れない（メール障害時に入口も塞がる）。
- Cloudflare Access（**50人まで無料**＝2026-08-06にWeb検索で複数の解説記事から確認。契約前に公式ページで再確認）でこの方式が作らずに実現できる。

### 案イ：ID＋パスワード方式（いつものやり方）

- 良い点＝4人が既に知っている型。メールに依存しない。
- 弱い点＝パスワードを紙に書いて貼る等の事故が起きやすい（初心者4人の実情ではこちらが心配）。

**★推し＝案ア**（初心者にとって「覚えない」が一番安全）。ただしメール障害時の入口確保として
代表のみ案イの予備鍵を持つ、の併用も可。確定は司令塔。

## 4. パスワード類（秘密情報）の置き場

1. **リポジトリ・共有フォルダ・スプレッドシートに平文で置かない**（全事業共通ルールどおり）。
2. サーバー側の**.env（環境変数ファイル）**に置く＝Shopifyトークン・スプレッドシートの鍵・AIの鍵。
   .envはサーバーの中だけに存在し、Gitに入れない（.gitignore で機械的に除外）。
3. **LINEのパスワード**（代表が4人の画面で使ってよいと明言済み）＝
   サーバー側に**暗号化して**保管し、LINE画面の「パスワードを表示する」ボタンを押した時だけ復号して表示。
   **表示した人・日時が記録に残る**。画面に常時出さない・ファイルに平文で書かない。
4. メールのIMAPパスワード＝.env（表示機能は付けない。ダッシュボードが内部で使うだけ）。
5. ★受け渡し時も平文メール・チャットで送らない（手渡し・その場入力を原則にする）。

## 6. この構成で「壊れても止まらない」が成り立つ理由（再掲・要点のみ）

- ダッシュボードが落ちる → Webメール・Shopify・スプレッドシート・LINE・Boxを**直接開けば全業務が続く**
  （各画面に「いつもの画面を開く」ボタンを置くのはこの訓練を兼ねる）。
- Shopifyトークンは**読み取り専用**＝ダッシュボードの不具合が本番を書き換える事故を構造的に防ぐ。
- 台帳の正本はスプレッドシート＝ダッシュボードのデータベースが消えても台帳は無事。
