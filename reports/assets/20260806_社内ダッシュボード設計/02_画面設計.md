# 社内ダッシュボード 画面設計（2026-08-06・営業戦略T・第1版）

**★初心者4人が迷わないことを最優先にしたラフ。** ボタンの文言まで日本語で書いてある。
実装時にこのラフから変える場合は、変える理由を添えて司令塔へ（勝手な高機能化をしない）。

---

## 0. 言葉のルール（画面に出す言葉から専門用語を消す）

| 使わない言葉 | 画面で使う言葉 |
|---|---|
| ステータス | **いまどの段階か** |
| タスク | **やること** |
| アサイン | **担当** |
| アーカイブ | **済みの箱へ** |
| ログイン | **鍵をあける**（ボタン名＝「はじめる」） |
| 同期・リロード | **最新にする** |
| エラー | **うまくいきませんでした（もう一度押してください）** |
| ダッシュボード | **ホーム** |
| 未読・既読 | **まだ見ていない／見た** |

★エラー文には必ず「次に何をすればいいか」を書く。番号だけのエラーを出さない。

## 1. 全画面共通の枠

```
┌────────────────────────────────────────────────┐
│ あつぺくと ホーム   [今日やること][メール][LINE][作家さま][注文][SNS]  ○○さん │
└────────────────────────────────────────────────┘
```

- 上のボタンは**この6つだけ**。増やさない。いまいる画面のボタンは色が変わる。
- 右上に**自分の名前**が常に出る（「いま誰として操作しているか」を迷わせない）。
- どの画面にも「**いつもの画面を開く**」ボタンを置く（メールならWebメール、注文ならShopify、
  台帳ならスプレッドシート）。**ダッシュボードで困ったら、いつもの画面に逃げられる**ことを保証する。

## 2. トップ「① 今日やること」（開いた瞬間の画面）

```
┌─ 今日やること（8月6日 水曜日） ───────────────────────┐
│                                                        │
│ ■ お返事を待たせているもの                              │
│   □ メール：〔件名…〕 ○日待たせています   [開く]        │
│   □ LINE：〔作家さまのお名前〕 返事待ち ○日  [開く]      │
│                                                        │
│ ■ お金                                                 │
│   □ 金曜の入金確認：〔件数〕件           [確認する]      │
│   □ 月額：いま動いているのは〔件数〕件    [くわしく]      │
│                                                        │
│ ■ 止まっている方（作家さま）                            │
│   □ 〔お名前〕さま：原稿の段階で ○日 止まっています [開く] │
│                                                        │
│ ■ 期限が近い約束                                        │
│   □ 〔内容〕 …あと○日                    [開く]        │
│                                                        │
│ 今日やることが無い欄は、欄ごと出ません。                  │
└────────────────────────────────────────────────┘
```

- **見出しは4つまで**。それぞれ0件なら欄ごと消える（「0件」と表示して安心させるのは
  「お金」欄だけ＝金曜は0件でも「今日の入金確認：0件でした」と出す）。
- 各行の右のボタンは**必ず1つ**。「開く」を押せば該当画面のその項目に直接飛ぶ。

## 3. 「② メール」

```
┌─ メール ──────────────────────────────────────┐
│ [サービス窓口] [会社] [管理]   ←3つの受信箱をボタンで切替  │
│ 表示：[お返事が要るもの] [ぜんぶ] [セールス・迷惑（自動より分け）] │
│────────────────────────────────────────────│
│ ● 〔差出人〕〔件名〕                8/6 10:12   まだ見ていない │
│   要約：〔AIがつくった2行の要約〕                        │
│   [読む]                                              │
│ ○ 〔差出人〕〔件名〕                8/5 17:40   Bさんが見た   │
│────────────────────────────────────────────│
│ [いつもの画面を開く（Webメール）]                         │
└────────────────────────────────────────────────┘

読む画面：
│ 本文（原文そのまま）                                     │
│ ─ AIの下書き ─────────────────────────────       │
│ 〔返信の下書き〕                                        │
│ [この下書きを直す] [下書きを使って返信する] [下書きを使わない] │
│ ─ 記録 ─ 見た人：〔名前〕 返信した人：〔名前・日時〕       │
```

- **自動より分け**：セールス・スパムは「お返事が要るもの」に出さない。ただし**消さない**
  （「セールス・迷惑」の箱に残す＝間違って分けられた大事なメールを人が救えるように）。
- **返信の実体はメールサーバー経由で送る**（ダッシュボードは下書きを渡すだけ。第2段の作りで詳細確定）。
- 「誰が見たか・誰が返したか」が各メールに残る＝**二人が同じメールに同時に返す事故を防ぐ**。
  返信作業を始めたら「〔名前〕さんが返信を書いています」と他の人の画面に出す。

## 4. 「③ LINE」

```
┌─ LINE（作家さま窓口） ─────────────────────────┐
│ [LINEを開く]  ←公式アカウントの画面がひらきます          │
│                                                        │
│ ■ 対応の控え（こちらに記録してから閉じる）               │
│ 〔作家さまのお名前〕 [返事をした] [返事待ちにする] [済み]   │
│ ─ 最近の控え ─                                        │
│ 8/6 〔名前〕さんが〔作家さま〕に返信                     │
└────────────────────────────────────────────────┘
```

- 第1段のLINEは**「開くボタン＋控え」だけ**。LINEの中身をダッシュボードに写さない
  （自作を最小に。★LINE公式の複数人利用の仕様＝実測待ち（待4）。使えるなら控えはさらに簡素化）。
- パスワードの扱いは `03_技術構成の提案.md` §4（画面に平文を常時置かない・表示したら記録が残る）。

## 5. 「④ 作家さまの台帳」

```
┌─ 作家さまの台帳 ────────────────────────────────┐
│ さがす：〔お名前を入れる〕     ならべ替え：[止まっている日数] │
│────────────────────────────────────────────│
│ 〔お名前〕さま   いまの段階：素材まち（12日）  返事を待っている │
│ 〔お名前〕さま   いまの段階：原稿づくり（3日）  こちらの作業   │
│   …                                                   │
│────────────────────────────────────────────│
│ [いつもの画面を開く（スプレッドシート）]                   │
└────────────────────────────────────────────────┘

1人をひらいた画面：
│ 〔お名前〕さま                                          │
│ 申込 → 入金 → 素材 → 原稿 → 公開のご確認 → 公開 → 月額     │
│  ✔     ✔     ●いまここ（12日）                          │
│ 待っているもの：〔作品のお写真〕（8/1にお願い済み）          │
│ [段階をすすめる] [お願いの記録をつける] [メモを書く]         │
│ ─ 同意記録 ─ 規約：AR-K1 ／ 照合：★実測待ち（待1）        │
│ ─ これまでの記録 ─ 8/1 Bさんが素材のお願いを送付 …        │
```

- 段階は**7つ固定**（申込→入金→素材→原稿→公開のご確認→公開→月額）。増やしたくなったら司令塔へ。
- 「**何日止まっているか**」は日付から自動計算。**誰の返事待ちか**（作家さま／こちら）を色で分ける。
- 正本はスプレッドシート。この画面はスプレッドシートを読み書きしているだけ（1枚目の図のとおり）。

## 6. 「⑤ 注文」（EC工程・8段階のカード）

```
┌─ 注文 ────────────────────────────────────────┐
│ [動いている注文] [済みの箱]                              │
│────────────────────────────────────────────│
│ ┌ 注文カード ──────────────────────┐                │
│ │ 〔作品名〕（〔作家さまのお名前〕さま）      │                │
│ │ ①注文 ②作家さまに確認 ③見積 ④見積と納期の連絡          │
│ │ ⑤入金確認 ⑥引き取り手配 ⑦検品・来歴カード・出荷 ⑧到着確認 │
│ │  ✔    ✔       ●いまここ（2日）                        │
│ │ つぎにやること：見積をつくる [見積をつくる]               │
│ │ 期限：8/8までに購入者さまへ連絡                          │
│ └─────────────────────────────┘                │
│ [いつもの画面を開く（Shopify）]                           │
└────────────────────────────────────────────────┘
```

- 「見積をつくる」を押すと：作品の寸法・重さから**送料と保険料の目安**を出す（第3段・★待5）。
  それまで（第1〜2段）は**見積の手順書と電卓画面**（入れる欄＝本体・送料・保険料・関税等→合計が出る）。
- ⑦で「**来歴カードをつくる**」ボタン（第3段）＝作品情報から雛形に流し込んでPDFに。
- ⑧で「**作家さまにもお届けの完了をお伝えする**」の下書きが出る（文面の呼び出し＝定型文集から）。

## 7. 「⑥ SNS・名言集」

```
┌─ SNS・名言集 ──────────────────────────────────┐
│ ■ 今週のことば（ウィークリー・エピグラフ）                │
│   いま出ていることば：〔……〕（8/4の週）                  │
│   来週のことば：〔……〕 [来週のことばを選ぶ]              │
│                                                        │
│ ■ ことばの蓄えばこ                                      │
│   〔ことば〕〔どなたのことば〕〔出典〕 [追加する]            │
│   ★出典の無いことばは登録できません（捏造ゼロ）            │
│                                                        │
│ ■ SNSの予定                                            │
│   8/7 〔投稿の内容〕 担当：Aさん [済みにする]              │
└────────────────────────────────────────────────┘
```

- 名言集の管理＝メンバーAの作業場所。**蓄える→選ぶ→切り替える**の3動作だけ。
- ★サイトへの実反映（週替わりの切り替えがテーマにどう繋がるか）は**実装時にシステム開発Tが設計**
  （テーマ側の仕組みの実測が要るため、ここでは画面だけ決めて繋ぎは確定させない）。

## 8. ボタン文言の一覧（実装時にこのまま使う）

開く／読む／確認する／くわしく／最新にする／はじめる（ログイン）／
段階をすすめる／お願いの記録をつける／メモを書く／見積をつくる／
この下書きを直す／下書きを使って返信する／下書きを使わない／
返事をした／返事待ちにする／済み／済みの箱へ／来週のことばを選ぶ／追加する／
いつもの画面を開く（Webメール・スプレッドシート・Shopify・LINE・Box）

**★「削除」ボタンはどの画面にも無い**（消す操作は正本側の画面でだけ行う＝全体設計書§5）。
