## 5. hCaptchaに到達するかの確認＝★到達しました（どこまで自動／どこから人か）

自分で挙げた未確認（「送信は1件も行っていない」）のうち、**hCaptchaに到達するかまで**を確かめました。
**フォームの送信POSTだけを遮断**したうえで送信ボタンを押しています（**実際の送信は発生していません**）。

### 結果

| 段階 | 状態 |
|---|---|
| ページを開いた時点 | hCaptchaのscript・器・challenge要素とも**0件**＝**まだ存在しない** |
| 全項目を入力・選択・チェック | HTML5検証「通る」／送信ボタン「押せる」 |
| **送信ボタンを押す** | **hCaptchaのパズルが実際に出る**（`hCaptchaチャレンジ` iframe **320x400・見えている**／文言「パターンと異なる動物アイコンを選択してください」＋画像グリッド） |
| フォームのPOST | **発生していない**（hCaptchaが先に立つため、解くまでPOSTに到達しない） |

→ 画像＝`hcaptcha_reached.png`

### ★切り分け

- **自動で通せる範囲**＝ページを開く → 全項目の入力・選択・チェック → **送信ボタンを押して hCaptcha のパズルが出るところまで**。
  **ここまでは毎回自動で再現できます**（本日、幅390pxで実施）。
- **人の操作が必要な範囲**＝**hCaptchaのパズルを解く（画像を選ぶ）以降のすべて**。
  解かない限りフォームのPOSTは発生しないため、**送信後の画面・受信内容・自動返信メールは、人が解かない限り一度も確認できません**。
  これは「人間にしか解けないもの」＝代表にお回しする6区分の①に該当します。

### ★自分の測り方の誤りを1つ訂正

最初の計測では「`atspect.com` を含むPOSTを遮断」としたため、**hCaptcha自身の設定要求
（`https://api.hcaptcha.com/checksiteconfig?...&host=atspect.com&...`＝クエリにドメイン名が入る）まで巻き込んで遮断**しており、
パズルが初期化できず「見えていない」と出ていました。**URLのoriginで厳密に判定**するよう直したところ、上表のとおりパズルが実際に表示されました。
（＝「出ない」と報告する前に自分のスクリプトを疑う、の実例）
